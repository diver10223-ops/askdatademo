# 二期 SQL 安全基线

状态：V2.0 P352 已实现基线

- 使用固定版本 SQL AST 解析器按 MySQL/ClickHouse 方言解析；只接受单条只读查询表达式，AST 安全组件拥有最终拒绝权。
- 数据源账号必须只读；拒绝 DDL、DML、多语句、`INTO OUTFILE`、行锁以及 sleep/benchmark/外部表函数等副作用或资源消耗能力。
- 库、Schema、表和字段采用发布白名单；显式拒绝星号投影，跨 Schema 同名表不继承末级表名授权。
- 每个实际读取物理表的 SELECT、CTE、UNION 或子查询分支都必须有时间边界，并分别注入参数化机构数据权限；生产 Provider 缺失或空权限范围时拒绝执行。
- 强制最大返回行数、最大时间跨度、AST 节点数、JOIN 数和子查询数；数据源执行前必须执行 Explain，超过最大估算扫描行数时拒绝。
- SQL 参数保持参数化；敏感字段在结果快照前脱敏；日志不得记录凭证。L6 记录业务 SQL、权限注入后的实际 SQL、参数、AST/复杂度、Explain 估算、数据源、耗时、行数、降级和错误摘要。
- 自动化攻击矩阵覆盖越权库表字段、星号、DML、多语句、UNION/CTE/嵌套绕过、危险函数、导出、锁、超期、空权限、复杂度和扫描量超限；超时、取消和降级路径继续纳入七层回归矩阵。

客户联调时必须重新确认方言、库/Schema、表列白名单、时间字段、机构范围字段、最大扫描行数、只读账号及 Explain 权限；这些客户环境条件不得用本地模拟测试代替。
