# AskData V2.1—V2.3 开发前文档与数据交付矩阵

## 1. 总体原则

每个版本开始编码前至少完成需求、场景、七层标准、详细设计、数据设计、影响分析和执行计划；接口、数据库、原型、测试、验收、发布和追踪文件应在对应里程碑前冻结。V2.2和V2.3不能只依靠需求规格和任务清单直接开发。

## 2. 每版本必备文件

| 编号 | 文件类别 | 开发前/发布前 | 主要内容 |
|---|---|---|---|
| D01 | 需求规格说明书 | 开发前 | 范围、非目标、规则、FR/NFR、四状态和待确认项 |
| D02 | 标准演示场景清单 | 开发前 | 8个新增场景、角色差异、话术、异常分支和验收点 |
| D03 | 七层完整输入输出标准案例 | 开发前 | 每场景L1—L7输入、处理、输出、JSON、状态和错误 |
| D04 | 七层架构技术实现详设 | 开发前 | 组件、职责、流程、接口、代码结构、安全和调度 |
| D05 | 新增场景与初始化数据设计 | 开发前 | 指标、资产、角色复用、模板、Fixture、POC/Product数据 |
| D06 | 七层逻辑与全量修改影响分析 | 开发前 | 前后端、管理端、库表、接口、运维、测试和发布影响 |
| D07 | 执行计划与步骤说明 | 开发前 | 里程碑、任务编号、前置条件、退出门禁和顺序 |
| D08 | API与内部契约设计 | M1前 | 外部OpenAPI、Java/Python契约、错误码和兼容策略 |
| D09 | 数据库逻辑模型与迁移设计 | M1前 | 表字段、关系、索引、迁移、回退、保留和归档 |
| D10 | 用户端/管理端交互与原型 | 前端开发前 | 页面、状态、权限、空态、失败和操作流程 |
| D11 | 测试策略、场景矩阵与黄金数据 | 测试前 | 单元、契约、集成、权限、安全、性能、恢复和回归 |
| D12 | 验收计划与签字模板 | RC前 | Demo/POC/Product验收、证据等级和阻断项 |
| D13 | 发布、部署、升级、回退和恢复手册 | 发布前 | 制品、环境、迁移、备份恢复、监控和回退 |
| D14 | Release Notes、已知问题与兼容矩阵 | 发布前 | 新增、变化、限制、兼容、风险和客户未知项 |
| D15 | 需求追踪矩阵 | 全阶段 | 需求→设计→接口/库表→代码→测试→证据→发布 |
| D16 | 四状态制品Manifest | 发布前 | Demo/POC/Product地址、标签、提交、SHA256；客户交付为空 |

## 6. 还缺少但必须增加的共同文件

除用户已列出的文件外，三个版本还需要重点增加：

1. API与Java/Python内部契约设计及OpenAPI冻结文件。
2. 数据库逻辑模型、迁移、兼容和回退设计。
3. 用户端与管理端原型/交互规格，覆盖空态、失败、权限和长任务。
4. 测试策略、测试矩阵、黄金问题/黄金数据和证据目录。
5. 安全专项设计与威胁模型，尤其是任务DAG、主动通知、API/文档/SQL助手。
6. 性能容量模型和长稳方案。
7. 备份恢复、灾备、升级回退和数据保留方案。
8. Demo、POC、Product三状态构建与验收说明。
9. Release Notes、已知问题、兼容矩阵和客户未知项清单。
10. 需求追踪矩阵和风险/决策日志。

## 7. 编制顺序

每个版本建议按以下顺序准备：

```text
需求规格
→ 待确认规则和业务数据
→ 8场景设计
→ 七层输入输出标准案例
→ 技术实现详设
→ 初始化数据设计
→ 全量影响分析
→ API/数据库/原型设计
→ 执行计划和任务拆分
→ 测试策略和黄金数据
→ 开发实施
→ 验收/发布/恢复文件
```

V2.2和V2.3的上述开发前文件应在对应版本启动前完成，不要求在V2.1开发前一次性冻结具体业务数据；但文档模板、编号和范围应提前建立。
