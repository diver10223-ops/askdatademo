# AskData 产品 V2.2 需求规格说明书

> 文档版本：V0.1
> 产品版本：AskData V2.2
> 版本主题：智能分析、主动服务
> 编制日期：2026-08-14
> 当前状态：需求细化稿；业务规则和通知范围待确认
> 开发基线：V2.1正式Product标签
> 适用状态：Demo、POC、Product；Customer Delivery有客户后派生

## 1. 产品定位

V2.2定位为“单域智能分析与主动服务版本”：在V2.1可靠多任务和证据链基础上，从用户主动查询升级到异常发现、受控归因、趋势判断、订阅、预警、智能报告和驾驶舱解读。

V2.2不重新建设任务引擎；所有分析和主动服务均转化为V2.1版本化任务计划并受其权限、调度、状态、事实和审计约束。

## 2. 建设目标

1. 基于已发布指标和可信事实自动识别经营异常。
2. 使用确定性对比、下钻和贡献度方法形成可验证归因。
3. 支持用户订阅指标、查询和报告，在权限范围内主动执行。
4. 形成日报、周报、月报和驾驶舱解读，并保留事实证据。
5. 对数据不足、关键任务失败和预测不确定性进行显著披露。
6. 主动任务在触发时重新校验权限、配置、指标和数据有效性。
7. Demo、POC、Product同步提供V2.2能力并完整回归V2.0/V2.1。

## 3. 范围和非目标

### 3.1 范围

- 规则化异常发现。
- 同比、环比、历史区间和阈值判断。
- 受控根因归因、贡献度和维度下钻。
- 同口径机构、产品、渠道和时间段对比诊断。
- 规则化趋势判断；预测作为受控增强项。
- 指标/查询订阅、异常预警和站内通知。
- 智能日报、周报、月报。
- 驾驶舱指标解读。
- 报告中心、订阅管理、预警记录和人工确认。

### 3.2 非目标

- 多域联合分析和跨域授权。
- 未验证Text-to-SQL补数。
- 无证据的自由归因和因果推断。
- 自动执行支付、核销、授权、关账等业务写操作。
- 单域API、文档、实时流和知识图谱接入；属于V2.3。
- 外部SDK、Webhook和开放扩展节点；属于V2.3。
- 无人工确认的外部大范围通知。

## 4. 用户和权限

三个角色继续继承V2.0/V2.1权限，不新增角色或扩大机构、指标范围。

- 订阅创建时校验权限，触发时再次校验当前权限。
- 权限失效、指标停用或配置版本不可用时，订阅暂停并记录原因。
- 报告只能包含接收者当前有权查看的事实；分享打开时重新鉴权。
- 预警不能通过标题、摘要或通知内容泄露无权机构和指标。
- 主动任务的审计主体必须同时记录订阅所有者和系统执行主体。

## 5. 智能分析需求

### 5.1 异常发现

| 编号 | 需求 |
|---|---|
| FR-AI-001 | 支持固定阈值、同比、环比和历史区间四类异常规则 |
| FR-AI-002 | 异常规则必须绑定指标、粒度、机构范围、方向、阈值和有效版本 |
| FR-AI-003 | 数据缺失、延迟或口径变化时不得判定正常，必须输出不可判断原因 |
| FR-AI-004 | 同一异常支持去重、抑制、恢复和重复提醒间隔 |
| FR-AI-005 | 异常事件记录触发事实、规则版本、数据时间、严重等级和证据 |

### 5.2 归因和诊断

| 编号 | 需求 |
|---|---|
| FR-AI-006 | 归因计划只能使用已发布维度、指标关系和受控计算方法 |
| FR-AI-007 | 支持按机构、客户类型、产品、渠道和时间进行授权范围内下钻 |
| FR-AI-008 | 支持差值、占比、贡献度和排序，不将相关性表述为确定因果 |
| FR-AI-009 | 归因结论逐条引用成功任务事实和方法版本 |
| FR-AI-010 | 任一关键维度失败时披露未核实项，不输出“已完成全面归因” |

### 5.3 趋势和预测

| 编号 | 需求 |
|---|---|
| FR-AI-011 | 首版支持规则化趋势：连续增长/下降、拐点、波动扩大和区间偏离 |
| FR-AI-012 | 趋势必须展示观察周期、数据点数量和数据新鲜度 |
| FR-AI-013 | 预测功能必须配置最低样本量、算法版本、回测指标和适用范围 |
| FR-AI-014 | 预测结果必须区分历史事实、预测值和不确定区间 |
| FR-AI-015 | 样本不足、结构突变或回测不达标时禁止输出预测值 |

### 5.4 证据化分析回答

| 编号 | 需求 |
|---|---|
| FR-AI-016 | 回答区分事实、规则判断、推断和建议 |
| FR-AI-017 | 每条关键结论至少引用一个执行事实 |
| FR-AI-018 | 展示分析完成度、失败任务和未核实项 |
| FR-AI-019 | 模型只能润色规则和事实形成的结论骨架，不得新增数值和原因 |
| FR-AI-020 | 行动建议仅供辅助，不直接触发高风险业务操作 |

## 6. 主动服务需求

### 6.1 订阅

| 编号 | 需求 |
|---|---|
| FR-SVC-001 | 用户可订阅已发布指标、查询计划或报告模板 |
| FR-SVC-002 | 订阅包含频率、时区、机构范围、触发条件、有效期和通知渠道 |
| FR-SVC-003 | 支持启用、暂停、恢复、修改、立即执行和删除 |
| FR-SVC-004 | 订阅修改形成版本，历史执行绑定触发时版本 |
| FR-SVC-005 | 相同用户、对象和频率的重复订阅应提示合并或确认 |

### 6.2 预警

| 编号 | 需求 |
|---|---|
| FR-SVC-006 | 异常规则触发后创建可追溯V2.1任务计划，不直接由模型生成消息 |
| FR-SVC-007 | 支持提示、一般、重要、严重四级预警（等级待确认） |
| FR-SVC-008 | 支持去重窗口、抑制窗口、恢复通知和手动关闭 |
| FR-SVC-009 | 预警记录包含规则、事实、任务、通知和用户操作链路 |
| FR-SVC-010 | 外部发送前按策略执行人工确认或审批 |

### 6.3 智能报告

| 编号 | 需求 |
|---|---|
| FR-SVC-011 | 支持日报、周报、月报模板和按需报告 |
| FR-SVC-012 | 模板定义章节、指标、图表、分析规则、完成条件和审批要求 |
| FR-SVC-013 | 报告生成使用冻结模板版本、权限快照和数据时间 |
| FR-SVC-014 | 报告预览显示缺失章节、失败任务和未核实项 |
| FR-SVC-015 | 报告发布、撤回、重新生成、导出和分享均记录审计 |

### 6.4 驾驶舱解读

| 编号 | 需求 |
|---|---|
| FR-SVC-016 | 对已发布驾驶舱指标生成摘要、异常提示和受控下钻入口 |
| FR-SVC-017 | 解读使用驾驶舱同一指标版本和统计时间 |
| FR-SVC-018 | 页面数据与解释不一致时停止发布并告警 |
| FR-SVC-019 | 不允许读取用户无权查看的隐藏图表数据 |
| FR-SVC-020 | 支持从解读进入V2.1多任务追问，保留证据上下文 |

## 7. 第一轮：V2.2核心业务规则（建议基线/待确认）

| 编号 | 规则 | 建议基线 |
|---|---|---|
| BR-22-01 | 异常方法 | 首版固定阈值、同比、环比、历史区间；不默认启用复杂模型 |
| BR-22-02 | 归因方法 | 维度下钻+贡献度；明确“影响项”而非未经验证的因果 |
| BR-22-03 | 预测 | 作为增强项，首个正式版本可关闭功能开关 |
| BR-22-04 | 主动渠道 | 首版站内通知；邮件/企业IM作为增强项 |
| BR-22-05 | 报告类型 | 日报、周报优先；月报同步支持模板但可后续启用 |
| BR-22-06 | 外发确认 | 重要/严重预警和正式报告外发必须人工确认 |
| BR-22-07 | 触发权限 | 每次触发重新鉴权，权限失败自动暂停订阅 |
| BR-22-08 | 缺数策略 | 不补数、不生成未验证SQL；标记章节缺失或任务失败 |
| BR-22-09 | 预警去重 | 同规则、对象和事实窗口内合并，窗口建议24小时 |
| BR-22-10 | 报告事实有效期 | 生成时冻结；重新打开标注生成时间，不静默刷新历史报告 |
| BR-22-11 | 系统配额 | 主动任务计入订阅所有者及系统双维度配额 |
| BR-22-12 | 建议边界 | 只提供辅助建议，不自动执行业务写操作 |

## 8. 七层调整

| 层级 | V2.2要求 |
|---|---|
| L1 | 接入用户提问、订阅触发、预警触发、报告和驾驶舱解读任务 |
| L2 | 识别分析目标、异常/归因/趋势/报告意图；主动任务加载模板而非猜测意图 |
| L3 | 将分析方法转为V2.1任务计划，定义基线、下钻、完整性和报告章节依赖 |
| L4 | 匹配已发布指标、维度、规则和历史事实；校验权限和时效 |
| L5 | 生成SQL/受控计算/规则判断节点；仍禁止未验证模型SQL |
| L6 | 复用DAG调度，增加定时触发、去重、抑制、配额和通知主记录 |
| L7 | 输出事实、异常、影响项、趋势、预测不确定性、建议和未核实项 |

## 9. 数据库需求

在V2.1任务表基础上建议新增：

| 表 | 用途 |
|---|---|
| `ana_rule_definition` | 异常/趋势/归因规则定义和版本 |
| `ana_rule_release` | 规则审批发布快照 |
| `ana_event` | 异常事件、严重度、状态、事实和去重键 |
| `ana_attribution_result` | 方法、维度贡献和证据引用 |

| `svc_subscription` | 订阅主体、对象、频率、时区、权限状态和版本 |
| `svc_subscription_run` | 每次触发、任务request、结果和失败原因 |
| `svc_notification` | 渠道、接收者、内容摘要、状态和重试 |
| `svc_report_template` | 报告模板、章节、完成条件和版本 |
| `svc_report_instance` | 报告实例、事实时间、状态、审批和内容引用 |
| `svc_report_evidence` | 报告结论/章节与执行事实关系 |

## 11. 用户端和管理端

### 11.1 用户端

- 对话结果增加异常等级、影响项、趋势和事实/推断标签。
- 新增订阅入口、我的订阅、预警中心、报告中心。
- 报告显示生成时间、模板版本、完成度、未核实项和证据。
- 驾驶舱解读支持继续追问并进入V2.1任务计划。

### 11.2 管理端

- 分析规则、阈值、维度、严重度和版本管理。
- 订阅策略、触发器、配额、通知渠道和失败重试。
- 报告模板、章节、审批和发布管理。
- 预警/报告任务、通知状态、事实证据和审计下钻。
- 预测算法注册、回测指标和功能开关（若启用）。

## 12. 非功能要求

- 定时触发具备幂等键，重复调度不产生重复报告或预警。
- 计划任务跨服务重启可恢复，不漏执行、不重复外发。
- 通知发送与任务执行解耦，失败按渠道策略重试。
- 主动任务不得挤占交互查询全部资源，使用独立队列和配额。
- 监控订阅触发延迟、异常事件量、预警去重率、报告成功率和通知失败率。
- 敏感预警内容默认脱敏，外部渠道只发送摘要和受控回链。
- 报告导出携带版本、数据时间、权限水印和审计标识。

## 13. 四种状态

| 状态 | V2.2交付要求 |
|---|---|
| Demo | 内置时间推进和异常Fixture，可重复触发预警、报告和归因 |
| POC | 使用批准数据验证规则、订阅、报告和站内通知，完成结果对账 |
| Product | 正式调度、权限复核、通知治理、审计、容量、恢复和升级门禁 |
| Customer Delivery | 当前为空；有客户后配置真实规则阈值、渠道、模板和签字 |

## 14. 测试和验收

- 异常规则边界值、缺数、延迟、口径变化和恢复测试。
- 归因维度、贡献度、失败节点和证据一致性测试。
- 订阅创建、修改、暂停、权限变化、重复触发和时区测试。
- 预警去重、抑制、恢复、确认、外发审批和失败重试测试。
- 报告模板、章节依赖、部分成功、重新生成、发布和撤回测试。
- 三角色权限、通知泄露和分享重新鉴权测试。
- 调度重启、积压、公平性、长稳、备份恢复和升级回退测试。
- 完整回归V2.0 S01—S08和V2.1 MT01—MT08。

## 15. 仍需确认

1. 异常规则首批指标和阈值。
2. 归因允许的维度及贡献度方法。
3. V2.2.0是否启用预测，若启用需确定算法和验收门槛。
4. 首版通知是否仅站内，是否同步邮件/企业IM。
5. 预警等级、去重和抑制窗口。
6. 哪些预警、报告必须人工确认或审批。
7. 日报、周报、月报首批模板和业务负责人。
8. 主动任务队列、并发和成本配额。
9. 报告保存期限、导出格式和分享范围。
10. Demo时间推进和触发演示方式。

## 16. 需求追踪

所有FR-AI、FR-SVC和BR-22需求必须追踪到设计、配置/库表、接口、代码、自动化测试和验收证据。规则、模板和通知策略变更必须版本化并写入每日修改记录。
