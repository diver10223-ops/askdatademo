# AskData 产品 V2.3 需求规格说明书

> 文档版本：V0.1
> 产品版本：AskData V2.3
> 版本主题：单域数据扩展、企业治理、生态开放
> 编制日期：2026-08-14
> 当前状态：需求细化稿；首批数据类型、治理和开放范围待确认
> 开发基线：V2.2正式Product标签
> 适用状态：Demo、POC、Product；Customer Delivery有客户后派生

## 1. 产品定位

V2.3定位为“单域开放治理平台版本”：在V2.1任务引擎和V2.2智能分析基础上，将可信资产从数据库指标扩展到单域业务API、文档和准实时数据，同时补齐模型、成本、证据、安全治理，以及标准API、Webhook、SDK和受控扩展机制。

V2.3仍不进入多域；所有资产、能力和任务必须绑定一个既定业务域。V3.0再增加领域能力包、跨域授权和跨域协同。

## 2. 建设目标

1. 在单域内统一注册、授权和编排数据库、API、文档和准实时数据。
2. 建立模型路由、提示模板、质量评估、成本配额和降级治理。
3. 建立标准查询、任务、报告、订阅、Webhook和SDK能力。
4. 建立面向数据开发/指标管理员的SQL助手和候选能力发布流程。
5. 所有扩展节点可注册、审批、版本化、授权、限流、审计和停用。
6. 保证新数据类型不削弱V2.0—V2.2权限、安全、事实和证据边界。
7. Demo、POC、Product同步建设，并完整回归前序版本。

## 3. 范围和非目标

### 3.1 范围

- 单域业务API资产接入。
- 单域文档检索和引用。
- 准实时数据及数据新鲜度治理。
- SQL/API/检索/受控计算混合任务。
- 模型路由、版本、提示模板、评估和降级。
- 用户/角色/任务类型成本与配额。
- 任务完整性、证据链和内容安全增强。
- 标准开放API、Webhook、SDK/嵌入式组件。
- 受控任务扩展节点。
- 管理端SQL助手、自动验证、隔离测试、审批和发布。

### 3.2 非目标

- 自动领域识别和领域能力包。
- 跨域数据联合、跨域授权和跨域DAG。
- 多智能体协作。
- 普通用户执行未验证Text-to-SQL。
- 无审批的任意插件、任意脚本和业务写操作。
- 客户专属连接器直接进入通用产品主干。

## 4. 单域数据扩展需求

### 4.1 业务API资产

| 编号 | 需求 |
|---|---|
| FR-DATA-001 | 管理员可注册OpenAPI描述或手工定义的只读业务API能力 |
| FR-DATA-002 | API资产绑定业务域、所有者、用途、认证引用、请求/响应Schema和版本 |
| FR-DATA-003 | 每个操作标记只读/写入；V2.3任务引擎只允许审批通过的只读操作 |
| FR-DATA-004 | 支持参数白名单、超时、重试、限流、熔断、响应大小和字段脱敏 |
| FR-DATA-005 | API响应必须通过Schema、数据分类和权限校验后形成执行事实 |
| FR-DATA-006 | API停用、版本变化或认证失效时自动停用依赖能力并告警 |

### 4.2 文档检索

| 编号 | 需求 |
|---|---|
| FR-DATA-007 | 支持批准格式文档的上传/同步、解析、切分、索引和版本化 |
| FR-DATA-008 | 文档绑定单域、所有者、分类等级、适用机构、有效期和权限 |
| FR-DATA-009 | 检索结果必须返回文档、版本、页码/段落、更新时间和权限证据 |
| FR-DATA-010 | 回答区分数据库事实、API事实和文档依据，不将制度文字当成经营数值 |
| FR-DATA-011 | 文档撤回或权限变化后索引和缓存及时失效 |
| FR-DATA-012 | 防止提示注入文档改变权限、安全、工具选择和系统指令 |

### 4.3 准实时数据

| 编号 | 需求 |
|---|---|
| FR-DATA-013 | 资产记录事件时间、处理时间、刷新频率、延迟SLA和水位 |
| FR-DATA-014 | 查询和回答显式展示dataAsOf、新鲜度和延迟状态 |
| FR-DATA-015 | 不同时间点数据合并前必须通过时效兼容检查 |
| FR-DATA-016 | 超过最大允许延迟时不得标记为最新或正常 |
| FR-DATA-017 | 首版支持轮询/微批准实时，实时流式处理是否纳入待确认 |

### 4.4 混合任务

| 编号 | 需求 |
|---|---|
| FR-DATA-018 | V2.1 DAG扩展SQL、API、DOCUMENT_RETRIEVAL、CONTROLLED_COMPUTE和AGGREGATE节点 |
| FR-DATA-019 | 节点输入输出使用版本化Schema并执行类型校验 |
| FR-DATA-020 | API/文档节点失败按关键性裁决，不允许模型伪造替代事实 |
| FR-DATA-021 | 混合结果合并时校验机构、时间、粒度、单位和分类等级 |
| FR-DATA-022 | 所有节点统一记录attempt、成本、事实、证据和审计 |

### 5.2 成本和配额

| FR-GOV-008 | 配额接近阈值时预警，超限按策略拒绝、排队或审批 |
| FR-GOV-009 | 主动任务、交互任务和开放API使用独立预算池 |
| FR-GOV-010 | 成本数据脱敏且可审计，不记录原始秘密 |

### 5.3 完整性、证据和内容安全

| FR-GOV-012 | 结论引用SQL/API/文档事实，引用链可验证和导出 |
| FR-GOV-013 | 建立提示注入、敏感信息、恶意文档、越权工具和输出合规检查 |
| FR-GOV-014 | 报告发布、预警外发、扩展节点发布和高成本任务支持审批 |
| FR-GOV-015 | 审计链覆盖资产、模型、提示、SQL候选、扩展节点和开放调用 |

## 8. 第一轮：V2.3核心规则（建议基线/待确认）

| 编号 | 规则 | 建议基线 |
|---|---|---|
| BR-23-01 | 首批API | 只读、已审批、OpenAPI可描述的单域业务API |
| BR-23-02 | 文档格式 | PDF、DOCX、HTML、TXT；扫描PDF/OCR作为增强项 |
| BR-23-03 | 文档检索 | 引用必须带文档版本和位置，文档不得覆盖结构化数据事实 |
| BR-23-04 | 准实时 | 首版轮询/微批，暂不建设流式计算平台 |
| BR-23-05 | 模型治理 | L2、L7、SQL助手独立路由和评估门禁 |
| BR-23-06 | 配额 | 用户、任务类型、模型、数据源四维配额 |
| BR-23-07 | 开放API | 异步任务优先，兼容期不少于一个次版本 |
| BR-23-08 | Webhook | HMAC签名、5分钟防重放窗口、指数退避和死信 |
| BR-23-09 | SDK | 首批建议JavaScript/TypeScript和Java，Python作为增强项 |
| BR-23-10 | 扩展节点 | 首版只读、签名、审批和白名单；禁止任意脚本 |
| BR-23-11 | SQL助手 | 仅管理员；三类审核后发布；普通用户不可见候选SQL |
| BR-23-12 | 探索执行 | 仅隔离只读环境；结果不可用于报告、订阅和预警 |
| BR-23-13 | 多租户 | 是否进入V2.3待产品确认；默认不纳入2.3.0 |
| BR-23-14 | 多域 | 明确不纳入，所有资产和能力绑定单一既定域 |

## 9. 七层调整

| 层级 | V2.3要求 |
|---|---|
| L1 | 接入嵌入组件、开放API和Webhook相关任务，统一身份和调用方信息 |
| L2 | 在既定单域内识别数据库/API/文档需求，不自动识别或切换领域 |
| L3 | 选择已发布能力并形成混合任务计划，定义来源优先级和完整性 |
| L4 | 匹配数据库、API、文档和准实时资产，校验权限、版本和时效 |
| L5 | 编译SQL/API/检索/计算DAG，执行Schema、网络、成本和副作用门禁 |
| L6 | 调度异构节点，实施配额、熔断、重试、取消、事实标准化和审计 |
| L7 | 区分结构化事实、API事实、文档依据和推断，统一证据与未核实项 |

## 11. API需求

- `/api/v2.3/assets/apis`：API资产和操作管理。
- `/api/v2.3/assets/documents`：文档版本、权限和索引状态。
- `/api/v2.3/governance/models|prompts|evaluations`：模型治理。
- `/api/v2.3/governance/quotas|usage`：配额和用量。
- `/api/v2.3/webhooks`：Webhook注册、暂停、投递和重放。
- `/api/v2.3/extensions`：扩展节点注册、验证、审批和发布。
- `/api/v2.3/sql-candidates`：SQL候选生成、验证、试运行、审核和发布。
- 对外查询/任务/报告/订阅API使用独立公开契约和弃用策略。

## 12. 用户端和管理端

### 12.1 用户端

- 回答显示数据来源类型、版本、时间和引用。
- 文档依据可查看受权限保护的定位信息。
- 准实时结果显示新鲜度和延迟提示。
- 嵌入组件保持与主站一致的权限、任务状态和证据体验。

### 12.2 管理端

- API资产、文档、索引、数据新鲜度和依赖管理。
- 模型路由、提示模板、评估、成本和配额管理。
- Webhook、API客户端、扩展节点及投递记录。
- SQL助手、验证报告、审批、发布、影响分析和停用。
- 统一日志下钻到调用方、资产、节点、成本、内容检查和证据。

## 13. 非功能要求

- API和Webhook具备认证、签名、防重放、幂等、限流和最小披露。
- 外部网络访问默认拒绝，仅允许审批目标和DNS/IP策略。
- 文档解析、索引和检索实施恶意文件、宏、脚本和提示注入防护。
- 混合任务实施节点级熔断、资源隔离和成本上限。
- 建立软件物料清单、依赖漏洞扫描和扩展节点签名验证。
- 用量账本可对账，成本统计误差和延迟指标待压测冻结。
- 监控API成功率、文档索引延迟、模型质量、配额拒绝、Webhook投递和SQL候选门禁。

## 14. 四种状态

| 状态 | V2.3交付要求 |
|---|---|
| Demo | 内置API/文档/准实时模拟资产；SQL助手只展示固定候选和验证过程 |
| POC | 接入批准只读API、样例文档、模型和沙箱，验证开放接口与治理 |
| Product | 正式网络、秘密、权限、配额、签名、审计、容量、恢复和供应链门禁 |
| Customer Delivery | 当前为空；有客户后配置真实API、文档源、IAM、渠道和SDK集成 |

## 15. 测试和验收

- API Schema、认证、限流、熔断、重试、版本变化和敏感字段测试。
- 文档解析、权限、撤回、引用、恶意文件和提示注入测试。
- 新鲜度、水位、延迟和不同时间数据合并测试。
- 混合DAG类型、依赖、失败、部分成功和证据一致性测试。
- 模型路由、提示版本、评估、降级、成本和配额测试。
- 对外API兼容、Webhook签名/重放/死信、SDK兼容测试。
- SQL候选Schema、口径、权限、AST、EXPLAIN、沙箱和审批门禁专项。
- 安全、供应链、容量、长稳、备份恢复、升级回退和前序版本全回归。

## 16. 仍需确认

1. 首批业务API和负责人。
2. 文档来源、格式、分类等级、OCR和索引技术选择。
3. 准实时采用轮询、微批还是流式，以及时效SLA。
4. 模型路由策略、评估集和质量门槛。
5. 配额维度、默认额度和超限策略。
6. 首批公开API及认证方式。
7. Webhook事件、签名、重试和载荷范围。
8. SDK首批语言和嵌入组件范围。
9. 扩展节点首批类型、审批人和签名机制。
10. SQL助手审核角色、沙箱数据源和发布流程。
11. 多租户是否进入V2.3.0。
12. Product环境允许的网络、对象存储、向量检索和秘密管理基础设施。

## 17. 需求追踪

所有FR-DATA、FR-GOV、FR-ECO、FR-SQL和BR-23需求必须追踪到设计、资产/库表、接口、代码、验证器、测试和验收证据。任何候选SQL、扩展节点或开放接口均不得绕过审批发布。
