# 一期、二期真实性与完整性验收计划

> 版本：v1.0  
> 制定日期：2026-08-07  
> 适用范围：一期 Offline Demo + Mock POC；二期真实模型与真实数据源 POC  
> 核心原则：能运行不等于真实完成；模拟服务通过不等于客户环境联通；演示数字不等于业务口径通过。

## 1. 验收目标

本计划重新判断一期、二期是否“真实存在、真实执行、结果正确、证据可复核、交付可复现”。验收不接受仅凭页面截图、代码文件存在、接口返回 200 或报告自述得出完成结论。

一期重点证明：离线版确实不依赖服务和网络；POC 的前后端、七层、SQLite、SSE、权限、配置与审计确实执行；Mock/Fixture 均明确标识，不能伪装成真实模型或真实数仓。

二期重点证明：适配器不仅能对 WireMock 发送协议请求，而且能在指定验收环境连接真实 OpenAI-compatible、ClickHouse、MySQL，使用批准的数据集完成查询，结果可由源库 SQL 对账，凭据和失败策略符合要求。

## 2. 证据等级与完成判定

|等级|名称|可接受证据|能够证明|不能证明|
|---|---|---|---|---|
|E0|声明|计划、任务状态、人工描述|有人定义过目标|功能存在或可运行|
|E1|静态实现|源码、Schema、配置、构建产物|实现和资产存在|运行时正确|
|E2|自动测试|隔离环境测试、矩阵脚本、构建日志|仓库内行为可重复|外部系统真实可用|
|E3|协议仿真|本地 WireMock/Stub 的真实 HTTP 交互|协议、序列化、错误分支基本正确|客户端点、网络、鉴权、真实 SQL 正确|
|E4|真实环境|真实端点、脱敏连接证据、源库对账、Trace|部署环境端到端可用|业务口径已获业务认可|
|E5|业务签字|业务样例、口径对账表、验收人签字|业务结果正式认可|生产非功能指标长期稳定|

完成状态只允许以下四种：

- `PASS`：达到本条规定的最低证据等级且证据齐全；
- `CONDITIONAL PASS`：技术目标达到，但存在明确、已批准的非生产限制；
- `BLOCKED`：缺少环境、凭据、业务口径或验收人，无法完成高等级验证；
- `FAIL`：已验证行为不符合要求。

禁止使用“代码已写”“理论支持”“测试通过”替代 E4/E5。二期真实 Provider 的最终验收最低为 E4；涉及业务指标正确性的条目最低为 E5。

## 3. 通用验收控制

每次正式验收必须记录：代码提交 SHA、分支、依赖锁文件摘要、执行时间、执行人、环境标识、配置版本、数据集版本、命令、退出码、原始日志位置和缺陷编号。凭据只记录密钥标识或末四位，不进入文档、日志、截图和导出包。

验收环境从空数据目录启动，不复用开发者已有数据库；所有测试数据可恢复；失败后保留日志和数据库副本。自动验收必须返回非零退出码表示失败，不允许在脚本中吞掉异常或以 Fixture 静默替代 POC 主链路。

### 一期放行门槛

P1-01 至 P1-11 全部 PASS，P1-12 可在明确标记“演示临时内容”时给予 CONDITIONAL PASS。一期不得宣称已连接真实模型或真实业务数仓。

### 二期放行门槛

P2-01 至 P2-14 必须全部 PASS。若缺少客户端点、凭据或批准数据集，则 P2-03、P2-05、P2-06、P2-10 至 P2-14 标记 BLOCKED，二期整体只能表述为“仓库内实现及协议仿真通过，真实环境未验收”，不得表述为“二期真实完整完成”。

## 6. 执行顺序

1. 冻结代码、需求基线、数据集和验收环境，生成 SHA 与资产清单。
2. 从空目录执行一期自动检查，再做 Offline 断网和 POC 浏览器人工复核。
3. 执行二期协议、安全、失败策略测试，并确认一期回归。
4. 注入验收专用密钥，依次验证真实模型、ClickHouse、MySQL 诊断。
5. 执行真实 Provider 3×8×33 矩阵，保存脱敏 Trace 和 SQL 对账结果。
6. 由业务方执行黄金问题对账并签字；安全/运维分别复核凭据与恢复。
7. 汇总缺陷。严重级别 S0/S1 必须清零，S2 必须有书面豁免和关闭日期。
8. 形成最终验收报告、证据索引和签字页；未达到门槛时按实际状态发布，不修改事实口径。

## 7. 验收职责

|角色|职责|
|---|---|
|研发|提供可复现构建、测试、修复和技术证据|
|测试|独立执行矩阵、负向用例、回归并保管原始日志|
|数据/业务|提供黄金问题、标准 SQL、容差和业务签字|
|安全|复核凭据、日志脱敏、SQL 安全和权限边界|
|运维|提供目标环境、网络、密钥、部署和恢复演练|
|项目负责人|确认范围、豁免、最终状态和对外表述|

## 8. 当前计划执行边界

仓库内 E1—E3 检查可直接执行。E4—E5 必须由真实端点、真实凭据、批准数据集和验收人共同完成；缺少上述输入不是“通过”，而是 BLOCKED，并在执行记录中列明。
