# 产品V2.0 Java/Python服务职责与数据所有权

> 版本：V1.0  
> 日期：2026-08-12  
> 对应任务：P310  
> 执行入口：`PRODUCT_V2_EXECUTION_PLAN.md`

## 1. 冻结结论

产品V2.0采用“Java平台控制面 + Python问数执行面”：

~~~text
浏览器/调用方
      │
      ▼
Spring Boot平台服务（唯一外部入口、系统管理事实源）
      │ 内部版本化API、服务身份、幂等、超时、Trace
      ▼
Python NLQ引擎（L1—L7执行、模型与业务数据源访问）
~~~

Spring Boot拥有用户身份、权限、配置生命周期、审批审计和平台管理数据；Python拥有单次问数执行过程。生产数据库表只有一个写入所有者，禁止Java与Python无约束双写。

## 2. 服务职责

| 能力 | Java平台服务 | Python NLQ引擎 |
|---|---|---|
| 外部API与前端静态资源 | 负责 | 不直接暴露公网 |
| 统一认证、用户、机构 | 负责 | 只接收已验证主体 |
| 角色、权限和数据范围 | 计算并冻结快照 | 使用快照并再次执行安全校验 |
| 指标、维度、资产和场景管理 | 负责CRUD、审批、发布 | 只读已发布快照 |
| 模型、数据源配置 | 负责生命周期和秘密引用 | 按授权引用解析运行Provider |
| Session创建与历史 | 负责 | 不自行创建用户Session |
| Request接收、幂等、排队入口 | 负责 | 接收内部执行任务 |
| L1—L7执行 | 记录外部状态 | 负责 |
| SQL计划和完整SQL安全 | 管理规则、接收事实 | 负责生成、校验和拒绝 |
| 模型与业务数据源调用 | 不直连 | 负责 |
| SSE对外推送与断线续传 | 负责 | 产生版本化内部事件 |
| 取消 | 接收并持久化 | 传播到队列、模型和数据源 |
| 配置审批、发布、回滚 | 负责 | 按版本加载，不修改发布状态 |
| 操作审计 | 负责且只追加 | 上报执行事实 |
| 运行Trace和指标 | 汇总与查询 | 产生执行Span和指标 |
| 备份恢复与迁移 | 平台库负责 | 执行态存储按共同版本恢复 |

## 3. 数据所有权

### 3.1 Java唯一写入

- `iam_*`：用户、机构、角色、权限、外部身份映射；
- `meta_*`：数据源目录、表、字段、指标、维度和映射；
- `ai_*`中的管理配置、秘密引用和运行组合；
- `flow_*`：意图、参数、SQL模板、场景和用例；
- `sec_*`、`ops_*`：安全策略和运维配置；
- `cfg_*`：草稿、审批、发布、快照和回滚；
- `audit_approval*`和平台操作审计；
- Session主记录、Request受理记录和对外状态。

### 3.2 Python唯一写入

- 层执行事实；
- SQL、模型和数据源调用事实；
- 执行结果快照；
- 引擎内部事件和取消传播结果；
- 引擎执行错误和耗时。

这些事实通过内部API或事件接入平台查询模型。若物理上共用平台库，也必须使用独立Schema/账号并限制表级写权限。

### 3.3 共同关联但不共同修改

`session_id`、`request_id`、`parent_request_id`、`config_version_id`、`permission_snapshot_id`、`trace_id`和`idempotency_key`由Java产生并传递；Python只能关联使用，不能重写身份、权限或配置版本。

## 4. 调用方向

1. Java验证外部身份和权限，创建Session及不可变权限/配置快照；
2. Java接收问题、生成Request/Trace/幂等键并完成入口限流；
3. Java调用Python内部执行API，传递问题、上下文引用、权限快照和配置版本；
4. Python加载对应的只读发布快照，执行L1—L7；
5. Python持续返回层事件、SQL/Provider事实、结果引用和终态；
6. Java持久化对外状态并通过SSE向客户端推送；
7. 取消由Java记录后调用Python，Python向排队任务、模型和数据源传播并回报结果。

Python禁止反向调用Java管理写API。确需读取配置时使用版本化只读接口或由Java在执行请求中提供快照引用。

## 5. 内部契约最低字段

执行请求至少包含：

- `api_version`、`request_id`、`session_id`、`parent_request_id`；
- `trace_id`、`idempotency_key`和截止时间；
- 已验证用户、角色及机构标识；
- `permission_snapshot_id`及不可变权限内容/安全引用；
- `config_version_id`及Provider组合引用；
- 问题、场景、合法上下文和运行模式。

事件至少包含：`event_id`、`event_type`、`request_id`、`sequence`、`occurred_at`、层级、状态和脱敏载荷。错误统一包含稳定错误码、用户安全消息、可重试标志和Trace ID，不跨服务返回秘密或底层原始异常。

## 6. 迁移期读写矩阵

| 阶段 | 管理读 | 管理写 | 问数入口 | 七层执行 | 退出条件 |
|---|---|---|---|---|---|
| C0 当前基线 | Python/SQLite | Python/SQLite | FastAPI | Python | V1.x稳定标签 |
| C1 Java骨架 | Python主读，Java影子读 | Python旧写 | FastAPI稳定入口；Java独立入口 | Python | 契约和数据对账通过 |
| C2 数据迁移 | Java新库双读校验 | 只允许受控迁移写，不做业务双写 | 两入口仅测试 | Python | 数量、权限、配置版本一致 |
| C3 Java接管 | Java新库 | Java唯一写 | Java为V2入口 | Python内部服务 | E2E、回滚和稳定回归通过 |
| C4 旧接口下线 | Java | Java | Java | Python | Python管理API只读后关闭 |

禁止业务双写。迁移期间通过离线迁移、变更冻结、校验和短切换窗口保证一致性；发生问题按整体版本回滚。

## 7. 兼容与隔离

- `release/v1-v2-test`及其标签继续由FastAPI同源提供演示/POC，不依赖Java；
- V2.0使用独立端口、数据目录、平台库和显式入口；
- Java未就绪时不得修改稳定演示启动脚本；
- V2.0前端只调用Java外部API，Python内部地址不进入浏览器；
- 一期/二期修复通过hotfix回流V2.0，V2.0能力不反向进入稳定标签。

## 8. 明确禁止

- Java和Python同时维护一套可写管理后台；
- Python信任浏览器传入的角色或权限而不使用Java签发快照；
- Java绕过Python直接拼接并执行问数SQL；
- Python修改已发布配置、审批或权限；
- 跨服务同步调用无限等待、无截止时间或无幂等键；
- 以共享文件、前端种子或通用JSON作为V2.0日常事实源；
- 为兼容演示而让V2.0生产链路静默降级到Fixture。

- 稳定演示和V2.0入口隔离；
