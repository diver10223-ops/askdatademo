# NLQ 智能银行问数平台：需求确认与三期开发规划

> 状态：需求基线已确认，尚未开始代码开发  
> 适用范围：离线演示版、Python Mock POC、真实 Provider 二期、Java + Python 企业版三期  
> 基线来源：仓库现有用户端、后台管理 HTML，以及仓库内 NLQ 七层架构和八场景需求文档

## 1. 文档目的

本文集中保存需求澄清过程中已经确认的全部关键决策，并将其转化为可执行的三期开发规划。后续的架构设计、任务拆分、验收矩阵和代码实现均应以本文为基线；如需调整，必须记录变更原因、影响范围和新版本。

## 2. 总体目标

平台需要同时提供两种一期交付形态：

1. **离线演示版**：不安装开发环境、不启动任何服务，双击单文件 HTML 即可演示三个角色、八个场景、已执行层轨迹和 SQL。
2. **Mock POC 版**：运行于 GitHub Codespaces，Vue 与 FastAPI 真正联通，后台配置真实保存，七层 Python 代码真实执行，但模型与外部业务数据源仍使用 Mock；常规查询可以在 SQLite 模拟数仓中真实执行。

系统最终分三期落地：

- 一期：离线 Demo + Python FastAPI Mock POC；
- 二期：真实大模型和真实数据源；
- 三期：Java 管理平台 + Python NLQ 引擎企业版。

## 3. 已确认决策登记表

### 3.1 技术路线与交付形态（确认 1—15）

1. 接受“一套源码、两个演示产物”：单文件 Offline Demo 和 Codespaces FastAPI POC。
2. 离线版使用 IndexedDB 保存，支持 JSON 导入、导出和恢复默认；不承诺跨电脑自动同步。
3. 离线版采用一个单文件 SPA，同时包含用户问数端和后台管理端。
4. 云端 POC 环境确认为 GitHub Codespaces。
5. 一期 POC 采用单体、单端口、同源访问，不使用 Docker Compose 编排多服务。
6. POC 不做真实登录，继续通过前端角色下拉切换演示角色。
7. 一期 POC 的定义为：七层 Python 代码、权限、规则、参数校验和 SQL 模板真实执行；模型和业务数据源为 Mock；全部轨迹和配置真实入库。
8. 一期数据执行采用 A+B 混合：常规成功查询优先执行 SQLite 模拟宽表 SQL，特殊场景和异常路径使用 Mock Fixture。
9. 一、二期七层核心均使用 Python；三期平台管理迁移到 Java，七层 NLQ 核心继续使用 Python。
10. 三期由 Java 替换 Python 单体中的平台管理部分，形成最终企业版；不长期同步维护两套后台。
11. 一期即提供模型和数据源配置页面，但真实 Provider 标记为二期支持，不伪造连接成功。
12. 一期以演示稳定性优先：离线版永远可用、POC 零外部依赖、具备官方快照和演示就绪检查。
13. 八个场景沿用当前页面默认问句，同时允许一个场景维护多个用例；场景 8 增加季度取数和归因案例。
14. 二期首批目标适配器为 OpenAI-compatible 模型、ClickHouse 和 MySQL。
15. 一期验收不要求真实数据库、真实模型、VPN、生产证书、固定出口 IP 或 SSO。

### 3.2 后台范围、测试与配置（确认 16—32）

17. 后台功能一期达到基础可用，二期达到完整可用。
18. 一期只做三个演示角色及其权限，不做用户账号和登录体系。
19. 切换角色后清空当前聊天界面、保留旧会话记录、创建新 Session，并绑定新的权限快照。
20. 指标与维度字典一期可查看、编辑、保存，并影响 Demo 和 POC。
21. 一期完整管理 Mock 数据资产，包括逻辑数据源、表、字段、指标映射、优先级和模拟数据。
22. 模型配置一期支持 Mock 真实测试及 OpenAI-compatible 配置结构占位；真实连接在二期实现。
23. 数据源配置一期支持 Mock 和 SQLite 真实测试；ClickHouse/MySQL 只保存配置草稿并标记二期支持。
24. 七层固定顺序，只允许在安全范围内配置启停策略、延迟、展示、Provider 和场景覆盖；不得任意重排。

28. 配置支持草稿、发布、版本、回滚和官方快照恢复。
29. 一期保存会话、七层轨迹、SQL、拦截、结果和操作日志，并提供基础检索与 JSON 导出。
30. 合规管控一期基础可用，二期完整可用。
31. 运维配置一期基础可用；定时任务和复杂告警不属于一期核心范围。
32. 一期仍执行三角色、八场景的 Mock POC 最小冒烟矩阵；二期执行真实 Provider 完整 POC 矩阵。

### 3.3 七层、场景和轨迹（确认 33—52）

33. 唯一标准七层为：交互层、对话理解层、语义层、数据资产层、查询生成层、执行层、问数解读层。
34. 短路、拦截或等待输入后，只展示实际执行过的层；不展示未执行层，也不制造占位轨迹。
35. 八个快捷按钮按当前角色自动选择合规默认问句；场景 5 例外，专门选择角色对应的越权或涉密问句。
36. 场景 1 三角色默认均使用各自权限范围内的成功查数用例，并额外保留越权失败用例。
37. 场景 2 使用内置模拟 BI 页面，同时允许后台配置外部 URL；轨迹只展示 L1—L3。
38. 场景 3 的推荐项可点击，点击后作为同一 Session 中的新 Request 执行。
39. 场景 4 一期即支持执行多条 SQL，而不是限制为一条综合 SQL。
40. 场景 5 在 L2 前置拦截，只展示 L1、L2，不生成 SQL，不访问数据源。
41. 场景 6 默认准备两轮对话，但代码结构支持继续追问。
42. 场景 6 的越权条件变更会被拦截，且不会污染上一轮合法上下文。
43. 场景 7 支持可点击选项和自然语言两种补全方式。
44. 场景 7 的缺参请求和补全后请求保存为两个关联 Request；第一条只展示 L1、L2。
45. 场景 8 严格采用两轮独立七层：同一 Session、不同 Request、第二轮关联第一轮。
46. 场景 8 第二轮完成后继续保留上下文，允许用户进一步追问。
47. SQL 展示区分业务 SQL 和实际执行 SQL；Fixture、短路、拦截必须标明未执行 SQL。
48. 一期数据结构从开始即支持一个 Request 包含多条 SQL 执行记录。
49. POC 一期即使用 SSE 实时推送层级与 SQL 事件；离线版使用同一事件协议进行本地模拟。
50. 离线演示只展示简洁轨迹；POC 同时提供简洁轨迹和技术详情。
51. 配置采用 Session 级版本锁定；发布和回滚只影响新 Session，除非管理员强制清空活动会话。
52. 内置不可删除的 `Official Demo Baseline v1`，支持复制、导出和恢复。

### 3.4 契约、模型、SQL、SSE和数据保存（确认 53—70）

53. 每次请求保存 Session、Request、Parent Request、角色、权限快照、配置版本、场景、用例、模式和 Trace 等标识。
54. 七层实现统一 `LayerProcessor` 接口，共享 `PipelineContext` 和结构化 `LayerResult`。
55. 场景 3 在 L2 完成模糊推荐并终止，轨迹只展示 L1、L2。
56. L7 只能基于 L6 数据进行解读，不得查库、补数、修改原始结果或生成新 SQL。
57. 一期 Mock Model Provider 只参与 L2 和 L7。
58. Mock 模型采用“确定性 Fixture + 规则兜底”，相同条件必须返回相同结果。
59. 模型只负责要素提取，标准映射、参数校验、权限和合规均由代码最终裁决。
60. SQL 使用后台模板、命名参数和资产映射生成，不允许模型自由生成 SQL。
61. 一期不开发独立 SQL 安全功能；二期实现基础安全，三期实现完整安全。模板化、参数绑定和受控执行仍属于必要的代码正确性要求。
62. 多 SQL 失败策略：一期自动用 Fixture 补齐且不在最终用户回答中提示；二期演示模式同样静默降级；二期 POC 模式采用明确的失败或部分成功。POC 技术详情和审计日志始终记录真实降级事实。
63. SSE 事件持久化，支持 Event ID、断线重连、遗漏补发和页面刷新恢复，不重复执行请求。
64. 一期提供停止执行按钮，保存取消人、时间、终止层和取消状态。
65. 保存脱敏后的查询结果快照，并限制单次结果大小。
66. 平台配置库与模拟业务数仓使用两个独立 SQLite 文件。
67. 提供“恢复官方配置”“重置 Mock 数据”“完全重置”三种独立操作。
68. 接受本文第 11 节的一期后台页面清单。
69. 接受本文第 17 节的一期非目标清单。
70. 一期保留可测试性设计，但不追求完整单元测试和覆盖率。

## 6. 七层标准与终止规则

### 6.1 七层职责

| 层级 | 名称 | 核心职责 |
|---|---|---|
| L1 | 交互层 | 请求封装、文本预检、Session、角色和配置版本绑定 |
| L2 | 对话理解层 | Mock 模型要素提取、字典映射、缺参、权限、合规和推荐 |
| L3 | 语义层 | 口径归一、查询计划、意图路由、驾驶舱短路 |
| L4 | 数据资产层 | 数据源、表、字段、指标字段和 Provider 选择 |
| L5 | 查询生成层 | SQL 模板渲染、业务 SQL、实际 SQL、多 SQL 计划 |
| L6 | 执行层 | SQLite、Fixture、结果和执行元数据 |
| L7 | 问数解读层 | 仅根据 L6 结果生成表格、摘要和归因解读 |

### 6.2 只展示已执行层

| 情况 | 展示层级 |
|---|---|
| 正常查数、同比、归因 | L1—L7 |
| 输入预检失败 | L1 |
| 权限、合规、缺参、模糊推荐 | L1—L2 |
| 驾驶舱跳转 | L1—L3 |
| 资产不存在 | L1—L4 |
| SQL 生成失败 | L1—L5 |
| 数据执行失败 | L1—L6 |
| 解读失败 | L1—L7，L7 标记失败 |

未执行层不展示、不保存占位轨迹；请求表保存终止层和终止原因。

## 8. Mock Provider 与 SQL

### 8.1 Mock 模型

- 仅参与 L2 和 L7；
- 使用确定性 Fixture，未命中时规则兜底；
- 不负责权限和合法性最终裁决；
- 相同输入、角色、上下文和配置版本必须产生相同结果；
- 不随机生成业务数字、权限结果或 SQL。

### 8.2 数据执行模式

```text
SQLITE_EXECUTION
MOCK_FIXTURE
NO_QUERY_REQUIRED
BLOCKED_BEFORE_QUERY
```

- 普通成功查数优先执行 SQLite；
- 特殊用例、异常路径和演示降级使用 Fixture；
- 拦截、推荐、跳转和缺参不执行 SQL。

### 8.3 SQL 展示

- Offline Demo 展示 `PRESET_DEMO_SQL` 并明确标记为演示；
- POC 同时保存业务目标 SQL 和 SQLite 实际 SQL；
- Fixture 显示未执行 SQL、结果来自 Fixture；
- 拦截显示未生成 SQL；
- 驾驶舱和推荐显示无需 SQL。

### 8.4 分阶段安全

- 一期：不实现独立 SQL 安全模块，仅保留模板化、参数绑定、资产映射和受控 SQLite 执行；
- 二期：实现只读、单语句、SELECT/CTE、DDL/DML 禁止、白名单、时间范围、行数和超时等基础安全；
- 三期：实现 AST、多方言、成本、Explain、扫描量、查询取消、复杂子查询和绕过测试等完整安全。

### 8.5 多 SQL 降级

- 一期和二期演示模式：SQL 失败后可使用 Fixture 补齐，最终用户回答不提示失败；POC 技术详情和审计必须记录降级；
- 二期 POC：主 SQL 失败则失败；归因 SQL 失败可明确返回 `PARTIAL_SUCCESS`，不得用 Fixture 隐藏真实问题。

## 10. 八场景验收基线

### 场景 1：基础查数

- 总行：上海分行对公贷款，成功；
- 北京分行：北京分行对公贷款，成功；
- 零售主管：权限范围内零售贷款，成功；
- 另保留北京分行跨机构、零售主管查对公的失败用例。

### 场景 2：驾驶舱

- 总行：总行和分行总览；
- 北京分行：北京分行驾驶舱；
- 零售主管：零售信贷驾驶舱；
- 只执行并展示 L1—L3，不生成 SQL。

### 场景 3：模糊推荐

- L2 根据角色权限返回最多三个推荐问题；
- 只展示 L1、L2；
- 点击推荐后创建关联的新 Request 并重新执行。

### 场景 4：同比归因

- 三角色使用各自权限范围内用例；
- 一期即支持主查询、同比和归因等多 SQL；
- L7 只能根据执行结果生成结论。

### 场景 5：权限与合规

- 总行：涉密明细拦截；
- 北京分行：跨机构拦截；
- 零售主管：跨指标拦截；
- 只展示 L1、L2，不生成 SQL。

### 场景 6：多轮上下文

- 默认两轮，结构支持继续追问；
- 第二轮继承合法的机构、指标和时间；
- 每轮重新校验权限；
- 越权变更被拦截，但不污染合法上下文。

### 场景 7：参数补全

- 第一条 Request 在 L2 返回 `WAITING_INPUT`；
- 提供权限过滤后的选项，并支持自然语言补全；
- 补齐后创建关联的新 Request，从 L1 重新执行。

### 场景 8：两轮独立七层

- 第一轮只查当期数据，完整执行 L1—L7；
- 第二轮继承上下文、升级归因意图，再次完整执行 L1—L7；
- 同一 Session，不同 Request，以 Parent Request 关联；
- 第二轮后保留上下文，允许继续追问。

## 12. 配置版本与重置

配置状态为 `DRAFT`、`PUBLISHED`、`DISABLED`、`ARCHIVED`。编辑草稿不影响运行；发布和回滚只影响新 Session；现有 Session 锁定其配置版本。强制切换必须清理活动会话。

三种重置操作：

1. 恢复官方配置，不删除日志、不重置业务数据；
2. 重置 Mock 数据，不修改配置、不删除日志；
3. 完全重置，恢复官方配置和业务数据并清理日志，必须二次确认。

## 18. 风险与控制

### Offline 和 POC 行为偏差

共用场景 Schema、事件 Schema、TypeScript 类型、官方快照和展示组件；发布时执行默认结果对比。

### 多 SQL 静默降级掩盖问题

最终用户回答可按已确认规则保持连续，但 POC 技术详情、SQL 审计、后台降级统计和就绪检查必须记录真实失败与 Fixture 来源；二期 POC 禁止静默掩盖。

### 一期没有独立 SQL 安全

一期只能连接内置 SQLite，不提供任意 SQL 控制台，不接真实业务数据库；真实数据源启用前必须完成二期基础安全。

### SSE 断线

事件先落库、Event ID、Last-Event-ID、自动重连和历史补发，禁止重连导致请求重复执行。

### Codespaces 环境变化

固定 Dev Container 和依赖锁文件；使用单端口和零外部依赖；提供启动诊断；Offline Demo 作为现场兜底。
