# 第一期开发任务名称与执行提示词

> 关联基线：[DEVELOPMENT_PLAN.md](./DEVELOPMENT_PLAN.md)
>
> 使用方式：严格按 T01 → T15 的依赖顺序执行。每个任务的“执行提示词”可以直接交给代码开发 Agent；开始任务前必须重新读取本文件、开发规划和仓库范围内的 `AGENTS.md`。
>
> 范围结论：第一期的技术范围、功能范围、验收边界和非目标已经确认。场景的最终业务数字、Logo 等内容资料尚未逐字段重新确认，但已确定以现有 HTML 和 Word 文档生成 `Official Demo Baseline v1`，因此不阻塞开发。

## 1. 全局执行规则

所有任务必须遵守以下共同规则：

1. 不改变 `docs/DEVELOPMENT_PLAN.md` 中已确认的 1—70 项决策；发现冲突时停止扩大范围，在任务结果中列出冲突。
2. 一期只实现离线 Demo 和 Python Mock POC，不连接真实大模型、ClickHouse 或 MySQL，不实现登录、SSO 或 Java 管理平台。
3. POC 使用 Vue 3 + TypeScript、Python FastAPI、两个 SQLite 文件、单应用、单端口、同源 API 和 SSE。
4. 离线版构建为一个可双击打开的 HTML，用户端与后台端在同一 SPA 中，使用 IndexedDB 持久化。
5. 七层固定为 L1 交互、L2 对话理解、L3 语义、L4 数据资产、L5 查询生成、L6 执行、L7 问数解读。
6. 只展示和保存实际执行过的层；不得伪造未执行层的输入、输出或状态。
7. Mock Model 只参与 L2 和 L7；权限、合规、参数和字典合法性由确定性代码裁决。
8. SQL 通过模板和资产映射生成，不允许模型自由生成 SQL；一期不建设独立 SQL 安全引擎。
9. 离线 Demo 只显示简洁轨迹；POC 同时显示简洁轨迹与技术详情。
10. 一期只做必要的构建、联通、场景冒烟和输入输出测试，不追求完整单元测试覆盖率。
11. 每个任务只修改其职责范围内的文件；提交前运行适用检查、`git diff --check` 和 `git status --short`。
12. 不把密码、密钥或真实连接信息写入仓库、前端构建产物、Fixture 或日志。

## 4. 开发任务使用建议

1. 每次只启动一个任务，避免多个 Agent 同时修改共享契约、迁移或场景基线。
2. T01—T07 优先建立后端和契约闭环，再开始大规模页面开发。
3. T09、T10 完成后再实现后台配置，避免后台字段先于执行模型随意生长。
4. T14 必须复用同一套前端组件和契约，不得另写一套孤立的静态 Demo。
5. 每个任务完成后都要更新任务状态、验证结果和遗留问题；只有验收标准全部满足才进入下一项。
6. 如果业务展示数字后续发生变化，只新增 Baseline 配置版本，不修改已确认的七层、API 和数据结构。
