# 竞品生成式应用与智能问数方案（脱敏整理）

> 来源：用户提供的15页竞品方案文本。本文仅做结构化整理；已移除或泛化企业名称、产品名称、品牌标识和具体供应商名称，不代表对其实际交付能力的验证。

## 1. 方案定位

面向银行结构化数据场景，以自然语言问数为入口，把业务语义、指标口径、数据结构、行为特征和模型洞察组织为数据知识资产，并由低代码/应用平台完成权限约束下的查询、展示和审计。

核心主张不是让模型直接交付一段SQL，而是生成符合权限治理规范的受控查询应用、看板或下钻页面。

## 2. 行业典型问数链路

```text
意图识别与分流
→ Schema / Semantic Linking
→ 查询规划
→ SQL / MQL / 查询任务生成
→ 执行校验与结果展示
```

各阶段分别处理：

1. 查询、聚合、TopN等问题类型；
2. 表、字段、指标等语义资产；
3. SELECT、JOIN、WHERE等查询结构；
4. Prompt、模板或Agent驱动的任务生成；
5. 校验、图表和报表输出。

方案认为，无论采用Text-to-SQL、指标语义层还是Agent自校验路线，主要难点仍是意图识别、Schema Linking、多表关联和权限执行。

## 3. 行业痛点判断

### 3.1 理解和关联不稳定

- 业务问题表达模糊；
- 容易选错表或字段；
- 多表长关联链路容易出错；
- 单纯依靠向量相似度容易产生偏差。

### 3.2 权限和合规执行不稳定

- SQL技术正确不等于业务含义正确；
- 字段权限与数据范围复杂；
- 脱敏及审计要求高；
- 银行场景的错误与越权风险更高。

方案将核心难点归纳为：**理解准确性 + 执行合规性**。

## 4. 三类核心亮点

### 4.1 多层级意图识别

在问数前预加工业务对象、行为和特征，将自然语言问题拆解为五级意图：

| 层级 | 识别内容 | 示例 |
|---|---|---|
| L1 | 问题类型 | 查询、趋势、对比、归因、异常、预测 |
| L2 | 业务对象 | 客户、账户、交易、产品、机构、设备、渠道 |
| L3 | 业务目标 | 风险上升、客户流失、AUM下降、转化下降 |
| L4 | 分析路径 | 指标、维度、时间、下钻、对比 |
| L5 | 输出形式 | 图表、看板、客户清单、风险解释、行动建议 |

这里的L1—L5是**意图分类维度**，不是端到端系统执行层级。

### 4.2 Schema GraphRAG数据知识底座

将语言匹配提升为图节点匹配与关系路径推理。图谱候选节点包括表、字段、指标、业务对象、行为事件和模型特征；候选关系包括主外键、逻辑JOIN、指标依赖、业务对象映射、同义词和数据血缘。

其目标包括：

- 减少错表和错字段；
- 减少错误JOIN；
- 解释指标依赖与数据血缘；
- 在多轮追问中复用分析因子和路径；
- 为后续图模型学习积累结构化样本。

数据权限元数据可以属于整体数据知识资产，但不直接进入供大模型检索的Schema GraphRAG链路，而由受控执行层使用。

### 4.3 元数据驱动应用构建

```text
意图识别结果 + 权限定义
→ 元数据驱动应用平台
→ 受控查询应用 / 看板 / 下钻页面
```

平台能力覆盖身份认证、应用权限、数据权限、字段权限、数据范围、查询组织、脱敏展示和日志审计。

## 5. 五层数据知识资产

| 层次 | 主要资产 |
|---|---|
| Schema Layer | 表、字段、主外键、逻辑JOIN、数据血缘 |
| Business Semantic Layer | 业务对象、维度、同义词、分析主题 |
| Metric Layer | 经营指标、风险指标、客户经营指标、反欺诈监控指标 |
| Feature Layer | 客户、交易、设备和渠道的行为特征 |
| Insight Layer | 风险分、流失/转化倾向、异常标签、客户状态变化 |

权限、脱敏规则和执行控制不属于上述知识层，由受控执行平台管理。

## 6. 银行场景复杂性

1. 同一指标存在不同业务口径；
2. 多系统、多表、多字段和多关联路径并存；
3. 总行、分行、部门和客户经理的数据边界不同；
4. 客户、交易、设备和渠道行为持续变化；
5. 问数过程、数据路径与权限执行均须追溯；
6. 用户表达的是经营或风险目标，而非数据库问题。

## 7. 典型实施路径

```text
选定业务场景
→ 注册结构化数据源
→ 梳理业务对象、指标、字段和关系
→ 配置权限定义
→ 构建Schema GraphRAG
→ 验证高频问数
→ 生成受控查询应用
→ 沉淀历史链路和图学习样本
```

实施目标是逐步形成可治理、可复用、可演进的查询应用，而不是一次性直接生成SQL。

## 8. 受控分析示例

用户问题：“为什么本月AUM下降了？”

1. 识别问题类型为归因，指标为AUM，时间为本月对比上月；
2. 识别客户、产品、机构等对象，选用标准经营指标口径及分析维度；
3. 从Schema GraphRAG取得候选表、字段、JOIN和指标依赖路径；
4. 调用受控数据访问接口，执行身份及应用权限硬性校验；
5. 校验查询任务规则并执行，记录日志和审计事实；
6. 输出指标变化、主要贡献机构/产品、指标解释、归因路径、图表和可追溯查询链路；
7. 对“具体是哪些客户”“哪个产品贡献最大”等追问复用路径和继承上下文。

模型负责理解与规划，平台负责权限、校验、执行和审计。

## 9. 与常规方案的自我定位

| 能力 | 普通Text-to-SQL | BI Copilot | 竞品方案 |
|---|---|---|---|
| 业务目标理解 | 字面意图 | BI语义层增强 | L1—L5多层级意图 |
| 指标口径 | Prompt或文档 | 既有BI模型 | Metric Layer统一口径 |
| 多表关联 | 易错表/错JOIN | 受BI模型边界限制 | GraphRAG路径推理 |
| 权限脱敏 | 执行后补控制 | BI平台权限 | 查询生成前注入权限定义 |
| 多轮追问 | 主要依赖上下文 | 部分支持 | 路径复用与对象/指标继承 |
| 审计追溯 | 弱 | 中 | 问题、路径、执行全链路 |
| 最终交付 | SQL或结果 | 图表或分析卡片 | 受控查询应用、看板或下钻页 |

## 10. 界面与总体架构

### 10.1 用户界面

- 左侧为对话沟通区，展示问答、特征分析、趋势洞察和补充视角；
- 右侧为折线图等可视化组件；
- 右侧同时提供AI分析解释和趋势标注。

### 10.2 总体架构

架构从上到下包括：

1. AI基础模型及体验/API管理；
2. 智能应用管理，包括应用定义、检索、内容审查、引用归属、用户背景、提示词、多模态和函数定义；
3. 通用AI数据连接与工作流引擎；
4. 模型、敏感词、知识库等AI数据基础管理；
5. 组织部门、统一用户、受控数据访问、统一权限和统一元数据；
6. 多种内外部基础模型适配。

## 11. 需进一步验证的关键问题

方案材料表达了目标架构，但未提供足够证据确认以下能力的生产成熟度：

- GraphRAG图谱如何建模、更新、评测和纠错；
- Feature/Insight Layer是否为现成交付能力；
- “受控查询应用”是临时页面、固定模板实例，还是可独立发布维护的应用；
- 多表路径推理的黄金集准确率及失败处置；
- SQL AST、成本、扫描量和超时门禁的实现细节；
- 多任务失败、部分成功、取消、重试和恢复机制；
- 权限快照、配置版本和多轮事实复用的失效规则；
- 客户环境中身份、密钥、审计、防篡改和灾备的验收证据。
