竞品智能问数方案与AskData V2对比分析

对比基线：竞品15页脱敏方案与仓库中的AskData V2.0/V2.1产品基线。竞品结论来自方案文本，不等同于已验证的生产能力；V2后续版本规划不计入V2当前能力。

1. 执行摘要

去除品牌信息后，双方属于同一“企业级受控智能问数”赛道：产品定位、主链路、指标治理、权限安全和审计理念高度重合。

  • 总体方案重合度：约75%—85%。
  • 实质差异度：约15%—25%。
  • 竞品主要差异：Schema GraphRAG、行为事件Feature/Insight Layer、受控查询应用生成。
  • AskData V2主要差异：七层确定性执行、多任务DAG、节点级权限与安全门禁、事实裁决、失败恢复和企业控制面治理。

2. 共同能力

双方都覆盖：

  1. 自然语言理解与意图识别；
  2. 指标、维度、表和字段等语义资产映射；
  3. 统一指标口径和同义词；
  4. 受约束查询生成与结构化数据源执行；
  5. 身份、角色、机构、指标、表和字段权限；
  6. 只读查询、脱敏、日志与审计；
  7. 文本、表格、图表及多轮追问；
  8. 模型负责理解/表达，确定性平台负责权限、执行和最终事实。

4. 竞品相对V2的优势

4.1 Schema GraphRAG

V2具备指标、维度、表、字段、同义词和血缘等资产，但当前资产匹配主要依赖已发布映射和查询模板；V2.1还明确不建设知识图谱。竞品提出图节点检索与JOIN/指标依赖路径推理，是最清晰的架构差异。

4.2 行为特征与模型洞察

竞品把客户、交易、设备和渠道行为特征，以及风险分、流失倾向、转化倾向和异常标签纳入问数底座。V2以结构化经营指标和受控查询事实为主，尚未形成独立Feature/Insight Layer。

4.3 受控应用生成

竞品声称最终生成权限约束下的查询应用、看板或下钻页面。V2当前主要交付问数答案、图表、证据、执行轨迹和驾驶舱导航，并未把动态生成可发布低代码应用作为核心能力。

5. V2相对竞品的优势

5.1 七层确定性责任链

V2明确区分请求接入、问题理解、意图参数、语义规划、资产映射、安全执行和事实回答，并规定模型不裁决权限、不绕过SQL安全、不脱离结果作答。

5.2 多任务DAG和生命周期

V2.1可以把一个综合问题拆分为独立可验证节点，记录依赖、关键性、输入输出Schema、计划版本和用户确认；执行支持串并行、排队、取消、定点重试、恢复和事实复用失效检查。

5.3 节点级权限与SQL门禁

权限在请求开始时冻结，并在每个节点对指标、机构、表、字段和数据范围再次校验。SQL还必须通过AST只读、参数绑定、时间范围、结果行数、复杂度和扫描成本检查。

5.4 成功事实裁决

V2区分成功、部分成功、失败和取消。关键事实失败时禁止输出完整排名、完整归因或“整体正常”等结论；L7只接收成功事实并显式披露未核实项。

5.5 企业控制面

V2冻结Java控制面与Python执行面的职责、数据所有权和调用方向，覆盖身份权限、配置审批、发布回滚、审计、幂等、SSE、取消及迁移，降低权限漂移和无约束双写风险。

7. 竞争定位建议

不宜使用“比竞品更会生成SQL”作为卖点。建议强调：

  1. 可验证任务执行系统：复杂问题形成可确认、可调度、可恢复的DAG；
  2. 权限贯穿每个节点：入口、规划、资产、SQL、执行、重试和复用均不越界；
  3. 成功事实驱动回答：模型不能补齐失败事实；
  4. SQL结构与成本双门禁：不仅判断只读，还控制范围和资源消耗；
  5. 控制面与执行面分权：审批、发布、回滚、审计和运行事实有明确所有者。

8. 对竞品的验证清单

正式竞争评估前，应要求演示或材料证明：

  • GraphRAG的图谱构建、增量更新、冲突处理和黄金集准确率；
  • 错表、错字段和错JOIN的量化对比；
  • Feature/Insight Layer是产品能力还是项目定制；
  • 查询应用能否独立发布、维护、回滚和重新授权；
  • 多任务部分失败、取消、重试和服务重启后的行为；
  • 权限或口径版本变化后，多轮路径复用如何失效；
  • SQL AST、成本、扫描量、超时和防注入的测试证据；
  • 客户身份、密钥、审计防篡改和灾备的交付边界。
