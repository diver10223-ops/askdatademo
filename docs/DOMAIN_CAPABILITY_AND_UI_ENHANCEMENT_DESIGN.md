## 1. 参考案例结论

本文不属于产品V2.0范围，不是V2.0完成门禁，也不指挥当前开发。产品V2.0完成并形成稳定标签后，再评审本文内容、确定V3.0范围并建立唯一执行计划。

参考案例体现的核心能力不是普通的“一问一条SQL”，而是：

~~~text
自然语言综合问题
  → 识别领域能力
  → 获取当前时间和上下文
  → 拆解多个只读查询任务
  → 按依赖串行或并行调用
  → 参数错误后按Schema受控修正
  → 汇总多来源结果
  → 区分正常、关注和待处理事项
  → 给出带事实依据的下一步建议
~~~

值得吸收的能力：领域知识封装、一问多查、过程可见、失败可解释、综合结论、证据与建议。不可直接照搬的部分：把内部命令、完整Schema和原始错误默认暴露给普通用户，以及让模型绕过正式权限、安全和审批机制自由调用工具。

本产品将截图中的运行时“Skill”定义为**领域问数能力包（Domain Query Capability Pack）**，代码和数据库统一使用`domain_pack`。它与Codex研发Skill完全不同：领域能力包属于正式产品，由平台数据库管理并参与在线七层执行；Codex Skill只用于内部研发、验收和交付自动化。

## 2. 新增产品能力

### 2.1 领域能力包

首批建设三个领域：

| 领域 | 首批能力 | 典型综合问题 |
|---|---|---|
| 经营管理域 | 指标查询、同比环比、机构对比、归因、综合经营巡检 | 本月各机构经营情况怎么样，有哪些需要关注？ |
| 财务域 | 预算执行、收支、未处理事项、结账状态、财务异常巡检 | 还有哪些财务事项没有处理？ |
| 审计域 | 高风险操作、权限变更、敏感访问、配置发布追溯 | 最近一周有哪些高风险操作？ |

后续可扩展风险管理、零售信贷、对公业务、资金、运营、合规和人力资源域。每个能力包包含：

- 领域编码、版本、负责人、适用角色和机构；
- 术语、同义词、意图和歧义规则；
- 指标、维度、单位、精度、时效和业务口径；
- 参数Schema、必填项、缺参提示和权限过滤后的补全选项；
- 查询计划、子任务、依赖关系、SQL/API绑定和失败策略；
- 权限、敏感等级、脱敏、导出和跨域限制；
- 完整性、对账、容差和异常判断规则；
- 回答结构、图表、证据引用、风险提示和下一步建议。

### 2.2 一问多查与查询计划

一个用户Request允许产生一个结构化查询计划，查询计划包含多个子任务。子任务可以是SQL、正式业务API、元数据查询或经批准的计算任务。

示例“还有哪些财务事项没有处理”：

~~~text
财务综合巡检
├── 余额与欠款检查
├── 未支付订单检查
├── 代金券有效性检查
├── 预算执行检查
├── 当前账期与结账检查
└── 资源包/额度检查
~~~

每个子任务必须记录：任务ID、能力、输入参数、依赖、数据源、模板/API、权限快照、状态、耗时、重试、错误、结果摘要、证据引用、是否关键以及对最终回答的贡献。

无依赖任务可在额度内并行；依赖任务必须串行。例如“确定账期→查询账单→按产品查明细”。并行度同时受全局、领域、数据源、用户和Session限额控制。

### 2.3 受控参数纠错与重试

参考案例出现订单查询参数错误后重新查询。产品应把这一能力做成确定性策略：

- Schema格式或枚举错误：允许基于正式Schema修正候选参数并重试一次；
- 网络、429或临时5xx：按Provider策略退避重试；
- 权限拒绝、SQL安全拒绝、敏感数据拒绝：禁止改写绕过和自动重试；
- 缺少业务参数：进入`WAITING_INPUT`，不得猜测关键条件；
- 修正前后参数、原因、次数和结果全部审计；
- 达到上限后终止对应子任务，不进行无限自循环。

### 2.4 综合结论与行动建议

L7应把多查询结果整理成固定层次：

1. 一句话结论；
2. 无需处理/正常事项；
3. 需要关注事项；
4. 待处理或高风险事项；
5. 关键数字和证据；
6. 未核实或失败项；
7. 建议下一步和可继续追问。

“建议下一步”只提供查看、核实、申请、跳转或发起流程等建议。支付、核销、关账、授权、配置发布和整改关闭等写操作必须跳转正式业务流程，并重新鉴权、确认或审批。

### 2.5 部分成功与完整性判断

综合问题不能因为部分查询失败仍回答“全部正常”。查询计划应定义关键任务与完整性条件：

- 全部关键任务成功：`SUCCEEDED`；
- 非关键任务失败且结论仍可成立：`PARTIAL_SUCCESS`，显著披露未核实项；
- 关键任务失败：`FAILED`或`INCOMPLETE`，禁止给出全局正常结论；
- 权限导致部分领域不可见：输出“无权限核实”，不能输出“无问题”；
- 所有结论可反查到成功的子任务和结果字段。

### 2.6 跨域组合

支持单域、主域+辅助域、经批准的跨域组合三种模式。跨域前必须校验用户是否同时拥有领域权限、指标口径和时间粒度是否一致、机构编码能否关联、数据能否联合使用以及敏感信息是否被扩大传播。模型不能临时创造未发布的跨域调用关系。

## 3. 七层执行调整

| 层级 | 新增职责 |
|---|---|
| L1 交互 | 保存展示级别、领域入口、综合问题标识和确认上下文 |
| L2 理解 | 识别领域、能力、意图、参数和缺参；产生候选能力列表 |
| L3 语义 | 将综合意图拆成语义子任务，确定指标口径和任务依赖 |
| L4 资产 | 为每个子任务选择经授权的数据源、表、字段或业务API |
| L5 查询生成 | 生成版本化查询计划DAG、SQL/API绑定和完整性条件 |
| L6 执行 | 并行/串行调度、限流、重试、取消、部分失败和结果校验 |
| L7 解读 | 只基于成功结果汇总，披露失败项，生成证据化结论与建议 |

AI可识别领域、抽取参数、生成候选任务和组织回答；正式代码负责能力包权限、Schema、任务依赖、SQL/API白名单、执行调度、重试边界、数值核验和最终状态。

## 4. 用户端功能优化

### 4.1 对话输入区

新增：

- 领域选择：自动识别为主，允许用户显式选择“经营管理/财务/审计”；
- 能力快捷入口：综合巡检、指标查询、异常检查、同比归因等；
- 输入提示随角色和领域变化，不展示无权限能力；
- 支持自然语言、补全按钮、时间快捷选择和可选语音输入；
- 综合问题提交前不要求用户理解数据表、API或SQL；
- 运行中提供“停止”，需要确认的写操作只显示“前往办理/发起申请”，不直接执行。

### 4.2 聊天消息结构

每轮回答建议由一个统一回答卡片承载，而不是把七层日志和最终结果混成连续文本：

~~~text
用户问题

AskData回答卡片
├── 状态头：处理中/等待补充/部分完成/已完成/失败
├── 领域与能力：财务域 · 综合财务巡检
├── 简明进度：正在核对6项，已完成4项
├── 最终结论
├── 关键指标/表格/图表
├── 正常、关注、待处理分组
├── 未核实与失败项
├── 数据口径与更新时间
├── 证据与执行详情（折叠）
└── 继续追问与下一步按钮
~~~

用户问题保留复制按钮、时间和所属Session；关联追问以轻量关系提示呈现，例如“基于上一轮的机构和时间继续分析”。

### 4.3 执行过程展示

参考截图的“已加载能力、已运行命令”有助于建立信任，但普通用户不应默认看到内部命令和完整Schema。建议提供三级展示：

| 级别 | 面向对象 | 默认内容 |
|---|---|---|
| 简洁 | 普通业务用户 | 领域能力、查询项数量、总体进度、最终结论 |
| 标准 | 管理人员/分析人员 | 子任务名称、状态、数据来源、更新时间、失败说明 |
| 技术 | 运维/审计/授权人员 | 七层轨迹、参数摘要、SQL/API事实、重试、Trace和耗时 |

进度区显示业务化名称，例如“正在核对预算执行”，不显示`python3 scripts/...`。每个子任务使用`等待/执行中/成功/失败/无权限/已取消`状态，并显示`3/6`总体进度。技术详情默认折叠并按权限脱敏。

### 4.4 结果展示组件

新增或优化：

- 摘要指标卡：应付、实付、差额、同比、完成率等；
- 通用表格：列配置、单位、合计、排序、分页、空值说明；
- 图表：趋势、对比、构成、排名和异常标记；
- 状态清单：正常、关注、待处理分组；
- 证据引用：数据源、账期/统计期、指标口径版本、Request/子任务编号；
- 数据新鲜度：明确“截至何时”，未来账期或无数据不能误报；
- 异常与限制：权限不足、数据未更新、查询失败、部分成功单独高亮；
- 数字一致性：摘要、表格、图表和文字必须来自同一结构化结果；
- 导出：按权限导出结果或证据，不导出内部秘密、完整Prompt和敏感SQL参数。

### 4.5 对话补全和继续追问

- 缺参卡片按“时间、机构、指标、产品”等分组展示选项；
- 选项必须经过权限过滤，不能先显示再拦截；
- 用户可点击组合，也可自然语言补充；
- 补全后创建关联Request并展示关系；
- 回答下方给出由能力包配置的继续追问，例如“查看账单明细”“按机构比较”“解释异常原因”；
- 推荐问题不得超出当前用户权限和已发布能力。

### 4.6 错误与空结果体验

面向用户的错误分为：需要补充、无权限、暂无数据、部分完成、系统繁忙和执行失败。不得直接展示Python异常、数据库错误或Provider原文。技术详情中保存脱敏错误码和Trace ID，方便支持人员定位。

“无数据”必须区分未来期间、源数据未到、筛选后为空和权限不可见；不能统一表述为“没有问题”。

## 5. 系统管理功能新增

### 5.1 领域能力包管理

新增一级管理域“领域能力”：

- 领域目录：编码、名称、说明、负责人、状态和适用范围；
- 能力管理：意图、触发示例、所需参数、关键任务和回答类型；
- 领域术语：同义词、歧义词、标准术语和版本；
- 领域权限：角色、机构、指标、功能和跨域授权；
- 能力预览：输入样例后预览命中的能力和计划，不执行生产查询；
- 完整性校验：缺指标、缺资产、缺任务、缺回答规则时禁止发布；
- 复制、启停、草稿、审批、发布、灰度、版本、回滚和审计。

### 5.2 查询计划设计器

提供可视化或表格化DAG设计：

- 子任务名称、类型、数据源、SQL/API绑定；
- 前置依赖、并行组、关键/非关键标记；
- 输入参数映射和输出字段映射；
- 超时、重试、并发、缓存和取消策略；
- 成功、空结果、失败和跳过条件；
- 汇总规则和完整性表达式；
- 测试运行、执行顺序预览和静态环检测。

能力包只引用已登记的SQL模板和API动作，不能在配置中嵌入任意Shell命令。

### 5.3 业务API与动作目录

在现有模型/数据源管理之外增加正式业务API目录：

- Provider、服务、动作编码、版本和环境；
- OpenAPI/Schema引用、请求与响应字段；
- 只读/写入分类和风险等级；
- 鉴权秘密引用、超时、限流和熔断；
- 可调用角色、领域和数据范围；
- 健康诊断、示例响应和脱敏策略；
- 写动作必须关联确认/审批流程，默认禁止被问数链路直接调用。

### 5.4 参数Schema与纠错策略

- 字段类型、必填、枚举、格式、默认值和示例；
- 关键参数是否允许默认；
- 缺参补全模板和权限过滤选项；
- 可纠错错误类型、最大次数和退避策略；
- 禁止纠错或重试的权限、安全和合规错误；
- 参数修订前后值的脱敏审计。

### 5.5 结果与回答策略

- 摘要、指标卡、表格、图表和清单布局；
- 正常/关注/待处理规则；
- 数值容差、单位、精度、合计和空值处理；
- 数据更新时间与口径版本展示；
- 未核实项和部分成功话术；
- 证据引用规则；
- 继续追问、跳转和行动建议；
- 模型回答输出Schema和数值一致性校验。

### 5.6 跨域组合管理

管理主域、辅助域、允许组合、关联键、粒度转换、敏感级别提升和审批要求。未批准组合不能由模型临时调用。

## 6. 后台运行与运维优化

### 6.1 查询日志升级

从“Request+SQL列表”升级为：

~~~text
Session
└── Request
    └── Query Plan
        ├── Task A
        │   └── SQL/API Execution
        ├── Task B
        │   └── Retry 1
        └── Task C
            └── Permission Denied
~~~

日志筛选增加领域、能力包、能力、计划状态、子任务、数据源、部分成功、重试和耗时。详情页提供时间线、DAG、输入输出摘要、错误链、证据和最终回答引用。

### 6.2 运行监控

新增：

- 各领域调用量、成功率、部分成功率和P95/P99；
- 能力命中率、未识别问题、缺参率和用户放弃率；
- 子任务队列、并发、超时、重试和取消；
- SQL/API Provider健康度、错误码和熔断；
- 结果空值率、数据新鲜度和口径异常；
- L7数值一致性失败和幻觉风险；
- 高频问题、低满意度回答和待优化能力。

### 6.3 调试与回放

- 使用脱敏快照回放，不重新访问生产源；
- 对比两个能力包版本的领域识别、计划和回答差异；
- 单步测试L2—L7，但不得在普通用户端暴露Prompt或秘密；
- 支持失败Request复制为测试用例；
- 能力包发布前运行黄金问题、负向用例和权限矩阵。

### 6.4 审批发布与变更影响

发布前计算受影响领域、能力、角色、SQL/API、指标和测试。高风险变更（跨域、敏感字段、写动作、关键任务、权限扩大）必须提高审批等级。活动Session锁定原版本，新Session使用新版本；支持灰度、快速停用和回滚。

## 7. 数据模型调整

建议新增：

| 表/对象 | 作用 |
|---|---|
| `flow_domain_pack` | 领域能力包主数据 |
| `flow_domain_pack_version` | 能力包版本与状态 |
| `flow_domain_capability` | 领域内可调用能力 |
| `flow_domain_term` | 术语、同义词和歧义词 |
| `flow_capability_parameter` | 参数Schema和补全策略 |
| `flow_query_plan_template` | 查询计划模板 |
| `flow_query_task_template` | 子任务模板 |
| `flow_query_task_dependency` | 任务依赖DAG |
| `flow_business_action` | SQL/API/计算动作目录 |
| `flow_result_rule` | 完整性、分类和对账规则 |
| `flow_answer_policy` | 回答布局、证据和建议规则 |
| `iam_domain_pack_permission` | 领域/能力包授权 |
| `run_query_plan` | Request实际查询计划 |
| `run_query_task` | 实际子任务与状态 |
| `run_task_execution` | SQL/API调用、重试和耗时 |
| `run_result_evidence` | 结论到结果字段的证据引用 |

现有`run_sql_execution`保留为SQL调用事实，并关联`run_task_execution`；模型调用和业务API调用使用各自事实表或统一执行父表加类型子表。查询计划和权限快照跟随Request版本锁定。

## 8. 接口与事件调整

新增或扩展契约：

- 查询提交可包含可选`domain_pack_id`、`capability_id`和展示级别；
- 查询详情返回领域、能力、计划、子任务、证据、完整性和建议；
- SSE增加`plan.created`、`task.started`、`task.completed`、`task.failed`、`task.retrying`、`plan.partial`等事件；
- 每个事件包含Request、Plan、Task、Sequence和Event ID；
- 普通用户接口返回业务化、脱敏信息；技术详情接口单独鉴权；
- 取消从Request传播到计划、排队任务、Provider和数据库执行。

## 9. 用户端建议布局

### 9.1 桌面端

~~~text
┌──────────── 领域/身份/会话 ────────────┐
│ 左侧：会话与能力入口 │ 中间：聊天主区 │ 右侧：可折叠执行详情 │
│                      │ 用户问题        │ 计划DAG/七层/证据    │
│                      │ 回答卡片        │ 技术权限控制         │
└───────────────────────────────────────┘
│ 输入框：自然语言 + 领域 + 附加条件 + 发送/停止 │
└───────────────────────────────────────┘
~~~

普通用户默认关闭右侧技术详情；演示模式可以打开标准或技术视图展示能力。

### 9.2 回答卡片视觉优先级

1. 结论和状态；
2. 关键数字；
3. 关注/待处理事项；
4. 表格和图表；
5. 未核实项与限制；
6. 口径、时间和证据；
7. 执行详情；
8. 继续追问和下一步。

不应像参考截图一样让大段命令参数和Schema占据主要阅读区域。

## 10. 验收新增项

至少增加以下测试：

1. 一个Request拆解多个子任务，计划和任务均可审计；
2. 无依赖任务并行、有依赖任务严格按顺序；
3. Schema参数错误只受控修正一次；
4. 权限和SQL安全拒绝不允许自动绕过；
5. 非关键任务失败返回`PARTIAL_SUCCESS`并披露；
6. 关键任务失败不输出“全部正常”；
7. 取消传播到未开始、执行中和Provider任务；
8. 普通用户看不到命令、秘密、Prompt、敏感SQL参数和原始异常；
9. 技术用户可按权限查看完整脱敏证据；
10. 摘要、表格、图表和文字数字一致；
11. 未来账期、数据未到、空结果和无权限使用不同话术；
12. 跨域组合必须同时满足领域权限与数据口径规则；
13. 能力包版本锁定、灰度、停用和回滚正确；
14. 推荐问题和补全选项全部经过权限过滤；
15. 写动作不能由问数链路直接无确认执行。

## 11. 产品V3.0候选实施建议

### 第一批：能力骨架

- 领域、能力、参数Schema、查询计划和子任务模型；
- 经营管理域从现有八场景迁移为首个能力包；
- 用户端回答卡片、业务化进度和执行详情分级；
- 一问多查的串行/并行、部分失败和取消。

### 第二批：财务与审计验证

- 财务综合巡检验证多API、多查询和行动建议；
- 审计风险巡检验证严格权限、证据引用和不可变审计；
- 查询计划设计器、业务API目录和回答策略管理。

### 第三批：跨域与运营优化

- 经营管理+财务等批准的跨域组合；
- 能力质量指标、低命中问题、回答评价和版本A/B对比；
- 客户项目按已确认业务域扩展能力包。

## 12. 候选完成定义

- 领域能力包成为在线业务能力的正式配置源，而非Prompt或前端种子；
- 一个问题可产生可审计、可取消、可回放的多任务计划；
- 用户端优先展示结论、数字、关注项和证据，技术过程按权限折叠；
- 系统管理支持能力包、计划、动作、参数、结果和回答策略全生命周期；
- 后台可按Request→Plan→Task→Execution完整追溯；
- 任何失败、无权限和数据缺失都不会被误报为“无问题”；
- 领域能力扩展不需要修改七层主框架，发布和回滚不影响活动Session；
- 新能力不破坏一期/二期稳定演示与POC。
