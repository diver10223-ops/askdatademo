# Text-to-SQL 分版本建设与治理规划

## 1. 总体决策

平台允许大模型生成“候选SQL”，但不允许仅凭免责声明将未验证SQL用于正式业务查询。普通用户可信问数链路必须满足权限、资产、业务口径、只读安全、查询成本和结果证据要求。

统一原则：

- 未验证候选SQL不执行、不出数、不进入最终回答。
- “SQL由大模型生成、结果未经验证”的提示不能替代安全与事实门禁。
- POC探索只能在隔离只读环境、人工确认和严格资源限制下运行，结果不得进入正式报告、订阅和经营结论。
- Product只执行已发布SQL能力或通过全部规定门禁的候选SQL。
- 候选SQL通过审核后，应发布为带版本、权限、口径和测试证据的正式查询能力。

## 2. 能力等级

| 等级 | SQL来源与状态 | 是否允许执行 | 是否可作为普通用户正式答案 |
|---|---|---:|---:|
| A 已发布 | 人工审核并发布的模板/查询能力 | 是 | 是 |
| B 自动验证 | 模型候选，通过该版本规定的全部机器门禁 | 受控执行 | 达到正式门禁后可以，并展示验证证据 |
| C 人工待审 | 机器安全检查通过，业务口径尚未审批 | 仅隔离环境人工确认后 | 否 |
| D 未验证 | 模型生成，尚未完成门禁 | 否 | 否 |

## 3. 分版本工作安排

### V2.0：受控SQL可信基线

定位：继续保持“自然语言理解→标准资产→受控模板→AST安全→权限范围→执行事实”的路径，不开放模型直接生成可执行SQL。

工作内容：

- 固化模型只参与L2理解和L7表达的边界。
- 维护已发布SQL模板、参数绑定、AST只读门禁、机构范围注入和审计。
- 在发布说明和用户/管理员手册中明确：V2.0不是开放式Text-to-SQL。
- 增加回归用例，证明模型输出SQL、未知表字段、写操作和范围绕过不能进入L6。

### V2.1：多任务可信执行

定位：建设单域任务计划和DAG，不同时引入开放式Text-to-SQL风险。

工作内容：

- 多任务节点仅允许已注册SQL模板和受控计算类型。
- L3只能引用已发布查询能力；L5生成节点SQL时继续使用模板/参数绑定/AST门禁。
- 每个任务节点独立执行表、字段、指标、机构范围和成本校验。
- 计划预览显示查询能力名称和口径版本，不向普通用户暴露未验证SQL。
- 重试只能重放已校验计划，不允许重试时重新让模型生成不同SQL。
- 增加多任务SQL安全测试：并行绕权、依赖注入、重试换SQL、计划调整越权和汇总污染。

明确非目标：V2.1不建设普通用户开放式Text-to-SQL，也不执行D级候选SQL。

### V2.2：可信事实上的智能分析

定位：异常分析、归因、订阅、预警和报告只能消费V2.0/V2.1可信执行事实。

工作内容：

- 智能分析不得为补齐缺失数据临时生成未验证SQL。
- 主动任务只能使用已发布指标、查询模板和版本化分析规则。
- 预警和报告记录SQL能力版本、事实时间、任务完成度和证据引用。
- 关键事实缺失时停止总体判断，披露未核实项。
- 增加“分析模型诱导生成SQL”“报告缺数自动补SQL”等禁止路径测试。

### V2.3：管理端SQL助手与候选能力发布

定位：首次正式建设Text-to-SQL辅助能力，但面向数据开发、指标管理员和授权测试人员，不直接面向普通业务用户开放。

工作内容：

1. SQL助手工作台
   - 输入自然语言、目标指标、数据域和期望输出。
   - 生成SQL草案、引用表字段、假设条件和风险说明。
   - 支持人工编辑、差异比较和版本保存。
2. 自动验证流水线
   - JSON/SQL解析与方言检查。
   - Schema、表、字段和关联关系校验。
   - 指标口径、聚合方式、时间粒度和去重规则校验。
   - 用户/角色/机构/行列权限检查和范围强制注入。
   - AST只读、禁止DDL/DML、危险函数和多语句检查。
   - EXPLAIN、扫描量、超时、行数和成本限制。
   - 隔离只读数据源执行和结果Schema校验。
3. 人工审批与发布
   - 数据开发审核技术正确性。
   - 业务/指标管理员审核业务口径。
   - 安全或数据管理员审核权限和敏感等级。
   - 审批通过后发布为正式查询模板/能力，生成能力版本和回归样例。
4. 生命周期治理
   - 草稿、验证中、待审批、已发布、已驳回、已停用状态。
   - 记录提示词、模型、候选SQL、人工修改、验证报告、审批和发布快照。
   - Schema或指标口径变化后自动标记受影响能力待复验。
5. POC探索模式
   - 仅授权人员、隔离只读库、人工确认、严格配额和显著“探索结果”标识。
   - 探索结果禁止被报告、订阅、预警和普通用户回答引用。

### V3.0：多域候选SQL任务节点

定位：在V2.3候选SQL治理基础上，将通过门禁的SQL能力用于多域任务编排；不重新建设SQL助手和安全引擎。

工作内容：

- 候选SQL节点必须绑定领域、能力包、数据源、指标口径和跨域授权关系。
- 在单节点安全门禁之外增加跨域授权、数据用途、联合粒度和敏感数据组合风险检查。
- 多域DAG只能引用已发布能力或通过该环境全部门禁的B级候选节点。
- 跨域事实合并前校验时间、粒度、机构、币种、分类等级和数据新鲜度。
- 任一关键领域节点未通过时，L7不得输出全局完整结论。
- 高风险跨域查询和外部系统调用保留人工确认/审批。

## 4. 版本交付物

| 版本 | 必备交付物 |
|---|---|
| V2.0 | SQL模板清单、AST门禁规则、权限范围测试、边界说明 |
| V2.1 | 多任务节点类型白名单、节点SQL安全矩阵、计划/重试一致性测试 |
| V2.2 | 分析事实来源规则、主动任务能力白名单、证据完整性测试 |
| V2.3 | SQL助手、候选SQL验证器、审批发布流程、隔离沙箱、能力生命周期和专项安全报告 |
| V3.0 | 领域/能力包绑定、跨域授权与组合风险门禁、多域事实一致性和人工确认策略 |

## 5. 验收红线

- 普通用户无法执行D级未验证SQL。
- SQL免责声明不能将失败门禁变成允许执行。
- 模型不能移除或改写权限范围条件。
- 任何执行SQL均可追溯到模板版本或候选验证/审批记录。
- Product和客户交付环境禁止使用Fixture或未审批探索SQL伪造成功。
- 结果页面必须区分已发布事实、自动验证事实、探索结果和未核实项。
