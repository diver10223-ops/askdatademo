## 第2页｜为什么建设

**核心结论**：传统取数难以同时满足效率、口径、安全和规模化运营要求。

- 业务取数依赖专业人员，响应链条长。
- 指标口径与数据入口分散。
- 大模型直接查库存在幻觉、越权和不可审计风险。
- 企业需要统一、安全、可运营的数据智能入口。

**布局**：四个痛点卡片 → 一个建设结论；结论置底部深蓝横条。

## 第3页｜产品定位与目标

**核心结论**：用自然语言连接“人、业务指标和受控数据源”。

- 对用户：更快、更简单地获得可信数据。
- 对业务：统一口径，沉淀高频分析场景。
- 对管理：权限、配置、发布、审计形成闭环。
- 对技术：模型和数据源可适配，能力可持续扩展。

**布局**：中心三角“人—指标—数据”，四项目标环绕。

## 第5页｜为什么结果可信

![七层可信问数机制](assets/15-seven-layer-overview.svg)

**核心结论**：七层机制把大模型能力放入确定性安全边界。

- L1—L5完成请求、权限、参数、计划和资产映射。
- L6执行参数化SQL和结构化安全校验。
- L7只能根据实际执行结果形成回答。
- 模型不裁决权限、不绕过SQL安全、不伪造事实。

**布局**：七级阶梯；L6、L7重点高亮；右侧放三条红线。

## 第6页｜用户端能做什么

![用户端查询结果原型](assets/06-user-query-result-prototype.png)

**核心结论**：覆盖从基础查数到趋势、对比、下钻和驾驶舱导航的主要经营分析入口。

- 机构和业务明细下钻。
- 角色权限过滤和驾驶舱智能导航。
- 多轮追问、缺参引导、推荐问法和结果图表。

## 第7页｜平台如何管理

![管理端能力地图](assets/17-admin-capability-map.svg)

**核心结论**：V2.0不只是问数页面，而是可配置、可审批、可监控的企业平台。

- 组织、用户、角色和数据范围权限。
- 指标、维度、数据资产、模板和场景。
- 模型、数据源、秘密引用和运行组合。
- 配置审批、发布、回滚和审计。
- 请求、SQL、Provider、队列和告警监控。

**布局**：五域管理轮盘，中间“统一管理事实源”。

## 第9页｜当前建设结果

**核心结论**：企业产品底座主体完成，产品基线正在收尾，客户交付尚需真实环境验证。

- 已完成：M0—M6、完整测试体系、迁移演练。
- 容量已有证据：30/50执行并发、200 QPS短突发、1300 SSE、30分钟峰值通过。
- 进行中：8小时长稳。
- 待完成：安全与发布审查、候选发布。
- 客户阶段：认证、数据库、模型、网络、容量、安全、灾备和业务签字。

## 第11页｜V2.0系统架构与能力边界

![技术架构图](assets/02-technical-architecture.svg)

**核心结论**：V2.0是安全可信问数平台基线，不是开放式通用智能体。

- Java控制面负责身份权限、配置发布、运行主记录和审计治理。
- Python执行面负责固定七层；模型只参与L2理解和L7解读。
- 以已发布指标、受控SQL模板和结构化数据源为主要数据能力。
- 不把任意跨域编排、主动预测、知识图谱和业务写操作列为V2.0已有能力。

**布局**：左侧架构图，右侧“已有/不属于当前基线”双栏；状态标记“V2.0产品基线”。

## 第12页｜产品定位如何演进

| 对比维度 | V2.0产品基线 | V3.0规划能力 |
|---|---|---|
| 定位 | 企业安全可信问数平台 | 智能经营分析与决策协同平台 |
| 入口 | 用户主动提问 | 提问、订阅、预警、报告、智能体 |
| 任务 | 一问一查或少量多SQL | 一问多查、多步骤计划DAG |
| 数据 | 结构化数据库为主 | 数据库、API、文档、知识和实时数据 |
| 输出 | 事实摘要、表格、图表 | 异常归因、预测、证据和行动建议 |
| 治理 | 权限、SQL安全、事实一致、审计 | 跨域授权、完整性、证据链、人工确认 |

**核心结论**：V3.0复用V2.0可信底座，扩展分析深度和任务复杂度，不降低安全边界。

## 第13页｜七层能力差异

| 层级 | V2.0产品基线 | V3.0规划能力 |
|---|---|---|
| L1 | 请求、会话、版本绑定 | 对话、订阅、预警和智能体任务接入 |
| L2 | 要素、上下文、缺参歧义 | 领域、能力及跨域需求识别 |
| L3 | 口径、意图、语义计划 | 综合问题拆解及任务依赖 |
| L4 | 表字段与指标映射 | API、文档、知识和实时资产匹配 |
| L5 | 受控SQL执行计划 | SQL/API/计算/检索计划DAG |
| L6 | 安全校验和数据执行 | 串并行、重试、质量及部分成功 |
| L7 | 事实摘要、图表、归因 | 证据化异常、预测和行动建议 |

**布局**：逐层横向比较；V3.0列统一加“规划”标识。

## 第14页｜V3.0七层规划架构

![V3.0七层规划架构](assets/21-v3-seven-layer-architecture.svg)

**核心结论**：七层从“可信查询流水线”升级为“领域能力驱动的多任务分析流水线”。

- 模型可识别领域、抽取参数、推荐任务和组织回答。
- 正式代码裁决权限、Schema、依赖、白名单、调度和最终状态。
- 关键任务失败必须披露未核实项，不能输出“整体正常”。
- 支付、核销、授权、关账等写操作必须重新鉴权、确认或审批。

**布局**：架构图全幅，右上角固定“V3.0规划能力”。

## 第15页｜V3.0演进方向

![产品V3.0能力演进地图](assets/20-v3-capability-map.svg)

**核心结论**：从“回答问题”走向“主动发现、深度分析、辅助决策和协同闭环”。

- 异常发现、根因归因、预测分析、智能报告。
- 专项分析智能体和多步骤任务编排。
- 指标知识图谱、文档融合和跨源分析。
- 移动端、企业IM、订阅推送和协作分享。
- 多租户、模型治理、成本配额和生态开放。

**布局**：V2.0底座 → V3.0五条增长曲线；首批建议试点“异常归因、智能报告、驾驶舱解读”。

## 第16页｜决策建议与下一步

![产品建设路径](assets/13-product-evolution.svg)

**页面文案**

1. 完成V2.0长稳、安全审查和候选发布，冻结产品基线。
2. 选择目标客户或试点单位，启动真实环境与黄金问题验证。
3. 同步建立V3.0需求池，按业务价值、数据成熟度、安全风险排序。
4. 优先试点可量化价值的异常分析和智能报告场景。

**布局**：左侧四步路线图，右侧列出需要决策的事项；底部结束语：“先把可信问数做成底座，再把智能分析做成能力。”
