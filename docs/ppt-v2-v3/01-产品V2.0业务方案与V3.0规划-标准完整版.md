## 统一视觉规范

- 比例与背景：16:9；暖白与纯白为主，浅蓝、浅绿用于内容分区；不使用影响阅读的大面积装饰。
- 字体：全篇微软雅黑；封面标题40—54pt，页标题30—36pt，正文15—18pt，图注13—16pt，备注10—13pt。
- 色彩：正文墨蓝`#182033`，主色湖绿`#17745F`，辅色商务蓝`#5C91C8`，浅底色`#F2F8F6`/`#EEF4FA`；橙色`#F47C3C`仅强调关键节点、结论和当前阶段。
- 排版：采用“左上两位编号 + 单行结论式标题 + 章节标签 + 细分隔线”母版；依据逻辑使用对照、流程、时间轴、中心辐射、矩阵、分层架构、原型图等版式，连续页面避免重复卡片阵列。
- 质感：仅使用轻微阴影、透明度和浅色层次，不使用影响专业性的强立体效果；不使用贯穿整页的左侧长实线。
- 页脚：左侧“企业级智能问数平台”，右侧页码；涉及状态的页面标注“产品基线/客户交付”口径。
- 动画：仅使用淡入、擦除和按层出现，单页不超过3组。

### 母版与组件规范

- 内容页顶部：左上角两位页码/章节码（湖绿或橙色，18pt），下方标题28pt、说明语16pt；标题区底部放1pt主色横线。
- 信息卡：白底、1.2pt主色描边、8—12px圆角；卡片标题前使用实心圆点，不使用复杂拟物图标。
- 对比页：左右等宽双卡，中间留0.35英寸；底部增加一条“关系判断/核心结论”通栏卡。
- 架构页：顶部为场景或渠道，中部为平台能力，底部为系统与数据对接；使用浅色分区底，不使用深色满版背景。
- 章节页：左侧放“/01”等大号编号和章节名，右侧可放抽象分层几何图；不使用照片背景。
- 表格页：表头商务蓝或湖绿底、宋体白字；正文隔行浅蓝，边框0.5pt白色；单元格内不超过两行。

## 第3页｜建设背景：数据使用的六类矛盾

**页面文案**

- 业务需求多，与数据服务资源有限之间的矛盾。

## 第12页｜七层职责说明

| 层级 | 核心职责 | 输出 |
|---|---|---|
| L1 | 建立请求、会话和追踪 | 原始问句、Trace |
| L2 | 标准化问题并受约束抽取 | 标准化问句、权限上下文 |
| L3 | 识别场景、指标、机构、时间 | 结构化业务参数 |
| L4 | 形成语义计划、选择已发布资产 | 查询计划 |
| L5 | 映射指标、维度、表和模板 | 受控资产映射 |
| L6 | 参数化SQL、安全校验并执行 | SQL事实、数据结果 |
| L7 | 基于执行事实校验并回答 | 文本、表格、图表、引导 |

**布局与展示**：三列表格，隔行浅蓝；L6、L7加粗。表下写“三条红线”：模型不裁决权限、不绕过SQL安全、不脱离结果作答。

## 第14页｜安全可信机制

![六道安全可信门禁](assets/18-security-gates.svg)

**页面文案**

- 身份、角色和机构权限快照固定。

## 第27页｜V2.0系统架构与能力边界

![技术架构图](assets/02-technical-architecture.svg)

**页面文案**

- 产品定位：面向企业经营管理的安全可信自然语言问数平台。
- Java控制面负责身份权限、配置审批、发布回滚、运行主记录和审计治理。
- Python执行面负责固定L1—L7问数链路；模型只参与L2理解和L7解读。
- 主要数据能力是已发布指标与字段映射、受控SQL模板及结构化数据源查询。
- V2.0以用户主动提问、一问一查或少量多SQL、事实回答为主要形态。
- 边界：不把通用智能体、任意跨域编排、知识图谱、主动预测和业务写操作表述为V2.0已有能力。

**布局与展示**：左侧或上部展示V2.0技术架构，右侧用“已有能力/明确边界”双栏说明；状态标记为“V2.0产品基线”。

| 任务形态 | 一问一查或少量多SQL | 一问多查、多步骤、多数据源计划DAG |
| 业务组织 | 场景、指标、模板和流程配置 | 可版本化、可审批的领域能力包 |
| 数据范围 | 结构化数据库为主 | 数据库、业务API、文档、知识图谱和实时数据 |
| 输出结果 | 事实摘要、表格、图表和追问 | 综合结论、异常归因、预测、证据和行动建议 |
| 治理重点 | 权限、SQL安全、事实一致性和全程审计 | 跨域授权、任务完整性、证据链、成本配额和人工确认 |

**布局与展示**：左右对比，V2.0使用湖绿“产品基线”，V3.0使用橙色“规划能力”；底部结论：“V3.0复用V2.0可信底座，不削弱权限、安全、事实和审计边界。”

## 第29页｜V2.0与V3.0七层差异

| 层级 | V2.0产品基线 | V3.0规划能力 |
|---|---|---|
| L1 | 请求封装、输入预检、会话及版本绑定 | 接入对话、订阅、预警、报告和智能体任务 |
| L2 | 要素提取、上下文、缺参歧义、权限合规初检 | 识别领域、能力、跨域需求和候选能力 |
| L3 | 口径归一、意图路由和语义查询计划 | 综合问题拆解、任务依赖、分析路径和完整性要求 |
| L4 | 匹配数据源、表、字段和指标映射 | 匹配授权指标、API、文档、知识和实时数据 |
| L5 | 受控SQL模板及单/多SQL执行计划 | 生成SQL/API/计算/检索组成的版本化计划DAG |
| L6 | SQL安全校验、数据范围注入和受控执行 | 串并行、限流、重试、取消、质量及部分成功判断 |
| L7 | 基于L6事实生成摘要、表格、图表和归因 | 生成证据化结论、异常、预测、未核实项和建议 |

**布局与展示**：三列表格，逐层横向比较；不得把右栏写成已完成。页脚标注“V3.0为候选规划，需经立项和客户场景验证”。

## 第30页｜V3.0七层规划架构与说明

**页面文案**：L1交互与任务接入 → L2领域理解 → L3语义规划 → L4可信资产匹配 → L5查询与任务编排 → L6执行与治理 → L7证据化分析与决策辅助。
