# 产品 V2.1—V2.3 演进范围建议

> 决策基线：V2.1—V2.3 均不考虑多域支撑。V2.1 建设多任务优化、用户体验和多任务执行；V2.2 建设智能分析和主动服务；V2.3 建设单域数据扩展、企业治理和生态开放。本文从现有 V3.0 规划中剔除领域识别、领域能力包、跨域授权、跨域调用和任意跨域编排等能力。

## 版本路线总览

| 版本 | 产品主题 | 核心能力 |
|---|---|---|
| V2.1 | 任务与体验升级 | 多任务优化、用户体验、多任务执行 |
| V2.2 | 智能分析升级 | 智能分析、主动服务 |
| V2.3 | 平台能力升级 | 单域数据扩展、企业治理、生态开放 |

版本依赖关系：V2.1 先建立可靠的任务规划、执行和交互基础；V2.2 基于可追踪的任务事实提供分析与主动服务；V2.3 再扩展单域资产类型、治理深度和外部集成能力。

## 一、V2.1：多任务优化、用户体验和多任务执行

### 1. 多任务优化

- 综合问题理解：识别一个问题中包含的多个分析目标、条件和期望输出。
- 问题拆解：将综合问题拆成多个可独立验证的子任务。
- 任务依赖规划：识别可并行任务、前后依赖任务和汇总任务。
- 计划预览与调整：执行前展示任务计划，允许用户删除、补充或重新生成任务节点。
- 参数复用：在子任务间复用时间、机构、指标、筛选条件和对比口径。
- 计划版本：任务计划调整后形成新版本，保留修改原因和前后差异。

### 2. 用户体验

- 多轮上下文增强：稳定继承时间、机构、指标、筛选条件和对比口径，支持“去年同期呢”“换成华东区”等自然追问。
- 指代与省略补全：识别“它、这个指标、刚才那家机构”等指代，缺少关键条件时只追问必要参数。
- 歧义澄清：指标、机构、时间或统计口径存在多个候选时，展示可选择的澄清项，不直接猜测。
- 会话内纠错与改写：允许用户修改上一轮条件、撤销筛选、重新执行，并清晰展示本轮继承和变更的条件。
- 推荐追问：根据当前事实结果提供趋势、同比、环比、构成和受控归因等后续问题。
- 回答结构优化：统一输出结论、关键数据、图表、口径/数据时间、证据来源及未核实项。
- 长任务对话反馈：在对话中展示任务拆解、执行进度、已完成/失败子任务，并支持取消和重试。

### 3. 多任务执行

- 计划执行接入：接收已确认的子任务计划，并固化任务输入、依赖和预期输出。
- 任务 DAG：支持串行、并行及前置依赖；V2.1 限定在单域、已发布资产和受控任务类型内。
- 多 SQL 与计算任务：支持多个查询、结果合并、同比/环比、占比、排序和受控派生计算。
- 调度治理：支持并发上限、超时、限流、重试、取消、幂等和资源配额。
- 部分成功：区分成功、部分成功、失败和取消；关键子任务失败时必须披露缺失结论，禁止给出完整性误导。
- 任务级可观测：记录计划版本、节点状态、耗时、错误、重试、数据量和执行轨迹。
- 任务恢复：对可重试节点单独重跑，不重复执行已成功且仍有效的节点。
- SQL边界：任务节点只允许已发布SQL模板和受控计算；不开放模型直接生成可执行SQL，重试不得重新生成不同SQL。

## 二、V2.2：智能分析和主动服务

### 1. 智能分析

- 异常发现：基于阈值、同比/环比和历史区间识别异常点。
- 受控根因归因：按已配置维度下钻、贡献度和对比规则生成可验证归因。
- 对比诊断：支持机构、产品、渠道和时间段等同口径比较，但不跨业务域。
- 趋势分析与预测：先提供规则化趋势判断；预测能力作为增强项，必须展示数据范围、方法和不确定性。
- 证据化结论：每条关键结论关联成功任务、查询结果、指标口径和数据时间。
- 行动建议：只输出辅助建议；支付、核销、授权、关账、配置发布等高风险写操作不在 V2.2 自动执行范围。
- 可信事实约束：异常、归因、预测和建议只消费已发布查询能力产生的成功事实，不允许为补齐缺失数据临时执行未验证模型SQL。

### 2. 主动服务

- 查询/指标订阅：按用户权限保存关注条件和推送频率。
- 异常预警：规则触发后生成可追溯的分析任务和预警消息。
- 智能日报、周报、月报：采用固定模板和已发布指标，支持自动生成、预览和人工确认。
- 驾驶舱解读：对已有看板指标生成摘要、异常提示和受控下钻入口。
- 协作分享：分享会话、任务结果或报告快照，并在接收方打开时重新校验权限。

## 三、V2.3：单域数据扩展、企业治理和生态开放

### 1. 单域数据扩展

- 业务 API 接入：将已审批 API 注册为可信资产，纳入权限、限流和审计。
- 文档检索融合：在单域内检索制度、口径说明和业务文档，回答中区分数据事实与文档依据。
- 指标关系增强：维护指标定义、维度、派生关系和影响关系；不建设跨域知识图谱。
- 实时/准实时数据：支持标注数据新鲜度和延迟，不同时间点的数据不得无提示混合。
- SQL、API、计算、检索的混合任务：允许在同一单域任务 DAG 中编排，所有节点必须来自已发布白名单。

### 2. 企业治理

- 模型治理：模型路由、版本管理、提示模板版本、效果评估和降级策略。
- 成本与配额：按用户、角色、任务类型统计模型与查询成本，设置并发和额度。
- 任务完整性治理：定义关键/非关键节点、完成度和结论可用条件。
- 证据链与审计：记录问题、计划、版本、执行事实、回答引用和人工操作。
- 内容安全：敏感信息脱敏、提示注入防护、输出合规检查和下载控制。
- 人工确认：报告发布、预警外发、建议转业务流程前保留确认或审批节点。

### 3. 生态开放

- 标准查询、任务、报告和订阅 API。
- Webhook/消息通知接口。
- 可控的任务节点扩展机制，扩展节点必须注册、审批、授权和审计。
- SDK 或嵌入式组件，便于已有门户、驾驶舱和业务系统集成。

### 4. 管理端SQL助手与候选能力治理

- 面向数据开发和指标管理员生成SQL草案，不直接向普通业务用户开放。
- 建设Schema、口径、权限、AST只读、EXPLAIN、扫描量、成本和隔离执行验证流水线。
- 候选SQL经人工审核和审批后发布为版本化查询模板/能力，再进入正式问数和多任务链路。
- POC探索模式仅限授权人员和隔离只读环境，探索结果不得用于正式报告、订阅、预警或经营结论。

## 四、V2.1—V2.3 明确不纳入

- 多领域自动识别与路由。
- 跨域指标、数据、知识的联合分析。
- 跨域授权、跨域能力包及跨域调用关系治理。
- 任意跨数据域、多智能体协作编排。
- 无人工确认的高风险业务写操作。
- 开放式通用智能体。
- 普通用户直接执行未验证Text-to-SQL及仅凭免责声明放行SQL。

## 五、各版本交付边界

### V2.1 交付边界

- 综合问题理解、问题拆解、任务依赖规划和计划版本。
- 多轮上下文、指代补全、歧义澄清和会话纠错。
- 综合问题拆解、单域任务 DAG、串并行、取消/重试、部分成功。
- 任务进度与执行轨迹、证据化回答、未核实项披露。
- 任务中心、结果快照和基础协作分享。
- 多 SQL 和受控计算；不承诺智能归因、预测和主动预警。

### V2.2 交付边界

- 异常发现、受控根因归因、对比诊断和趋势分析。
- 预测分析作为增强项，必须说明方法、数据范围和不确定性。
- 指标订阅、异常预警、智能报告和驾驶舱解读。
- 报告中心、订阅管理、人工确认和推送记录。

### V2.3 交付边界

- 单域业务 API、文档检索、实时数据和混合任务编排。
- 模型治理、成本配额、任务完整性、证据链和内容安全。
- 标准 API、Webhook、SDK、企业 IM 和受控扩展节点。
- 专项分析智能体可作为增强项，但必须限定为单域、只读和受控工具集合。

## 六、版本定位

- V2.1：“单域多任务问数版本”，从一问一查升级到连续交互、一问多查和多步骤可靠执行。
- V2.2：“单域智能分析版本”，从返回查询结果升级到异常发现、归因分析和主动报告。
- V2.3：“单域开放治理平台版本”，扩展数据资产、治理能力和生态集成。
- V3.0：集中解决多域能力组织、跨域授权和跨域协同。
