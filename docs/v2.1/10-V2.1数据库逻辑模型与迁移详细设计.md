# V2.1 数据库逻辑模型与迁移详细设计

## 1. 迁移原则

- 从V2.0 Flyway V16之后新增迁移，不修改V1—V16。
- 空库和V2.0升级均得到相同Schema。
- 核心状态规范化存储，JSON只保存扩展快照。
- 历史V2.0请求不强制回填DAG。

## 2. 新增表

| 表 | 主键和核心字段 | 关键约束/索引 |
|---|---|---|
| `run_task_plan` | id,public_id,request_id,plan_version,status,plan_json,permission_snapshot_id,config_release_id | UNIQUE(request_id,plan_version)，已确认不可覆盖 |
| `run_task_node` | id,public_id,plan_id,node_code,node_type,critical,status,input_json,output_schema_json,timeout_ms,max_attempts | UNIQUE(plan_id,node_code)，INDEX(plan_id,status) |
| `run_task_dependency` | plan_id,upstream_node_id,downstream_node_id,dependency_type | 复合主键；禁止自依赖；发布前代码无环校验 |
| `run_task_asset_binding` | node_id,asset_type,asset_id,asset_version,permission_decision_json,data_as_of_rule | UNIQUE(node_id,asset_type,asset_id) |

## 3. 现有表调整

- `run_request`：增加`current_plan_id,plan_status,total_tasks,succeeded_tasks,failed_tasks,skipped_tasks,cancelled_tasks,answer_version`。
- `run_sql_execution`：增加可空`task_node_id,attempt_id`。
- `run_provider_execution`：增加可空`task_node_id,attempt_id`。
- `run_sse_event`：建议增加可空`task_node_id`和索引；payload仍携带完整标识。
- `ops_retention_policy`：加入计划、节点、attempt、事实、claim和变更审计。

由于`run_request.current_plan_id`与`run_task_plan.request_id`循环引用，迁移顺序为：先建计划表→新增可空列→添加外键；创建请求时允许当前计划为空。

## 4. 状态约束

- 计划：DRAFT、VALIDATED、WAITING_CONFIRMATION、CONFIRMED、EXECUTING、COMPLETED、CANCELLED、INVALID。
- 节点：WAITING、READY、QUEUED、RUNNING、RETRY_WAIT、SUCCEEDED、FAILED、SKIPPED、CANCELLATION_REQUESTED、CANCELLED、TIMED_OUT。
- attempt：PENDING、RUNNING、SUCCEEDED、FAILED、CANCELLED、TIMED_OUT。

数据库CHECK与应用枚举必须一致；新增终态需要迁移和契约评审。

## 5. 一致性事务

- 创建计划、节点和依赖在单事务完成。
- 确认计划使用版本条件更新，防止并发覆盖。
- 节点状态迁移使用CAS：`UPDATE ... WHERE status IN (...)`。
- 写入成功事实和节点SUCCEEDED在同一事务完成。
- 事件使用request内序号分配器，状态提交后写入或采用事务外盒。

## 6. 保留、归档和恢复

- 计划/节点/attempt在线180天后归档；事实按分类和业务要求设置，默认90天。
- claim/evidence与结果快照同生命周期，不得先删证据。
- 备份必须包含应用发布包、数据库、秘密恢复材料、Manifest和SHA256。
- 恢复后按非终态节点和attempt对账，不重复执行已有有效成功事实。

## 7. 迁移验证

- 空库V1→最新。
- V16→V2.1迁移。
- 重复启动幂等。
- H2/PostgreSQL兼容测试。
- 迁移前备份、前向、回退恢复、再次前向和事实对账。
- V2.0历史请求查询和归档不受影响。
