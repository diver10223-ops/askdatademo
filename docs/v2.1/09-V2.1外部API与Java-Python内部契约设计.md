# V2.1 外部API与Java/Python内部契约设计

## 1. 原则

- V2.0接口保持兼容，V2.1使用显式版本路径和`schemaVersion=2.1`。
- Java控制面是外部入口和状态主记录；Python执行面不直接向普通用户开放。
- 核心计划、节点、attempt和事实使用明确字段，不依赖自由JSON解释状态。
- 所有写命令使用认证、授权、Trace ID和幂等键。

## 2. 外部API

| 方法 | 路径 | 权限 | 幂等 | 主要响应 |
|---|---|---|---|---|
| POST | `/api/v2.1/requests` | 登录用户 | `Idempotency-Key` | requestId、status、traceId |
| GET | `/api/v2.1/requests/{id}` | 请求所有者/授权管理员 | — | 总体状态、完成度、当前计划 |
| GET | `/api/v2.1/requests/{id}/plan` | 同上 | — | planVersion、nodes、edges、cost |
| PUT | `/api/v2.1/requests/{id}/plan` | 请求所有者 | `If-Match`计划版本 | 新计划版本和diff |
| POST | `/api/v2.1/requests/{id}/confirm` | 请求所有者 | 幂等键 | CONFIRMED/QUEUED |
| GET | `/api/v2.1/requests/{id}/events` | 同上 | Last-Event-ID | SSE任务事件 |
| POST | `/api/v2.1/requests/{id}/cancel` | 请求所有者/运维 | 幂等键 | CANCELLATION_REQUESTED/CANCELLED |
| POST | `/api/v2.1/tasks/{taskId}/retry` | 请求所有者/授权运维 | 幂等键 | attemptNo、status |
| GET | `/api/v2.1/requests/{id}/answer` | 同上 | — | claims、evidence、unverifiedItems |
| GET | `/api/v2.1/task-center` | 登录用户 | — | 分页任务列表 |

## 3. 核心请求

```json
{
  "schemaVersion": "2.1",
  "sessionId": "uuid",
  "parentRequestId": null,
  "question": "对比北京和上海分行一季度贷款、存款和不良率",
  "scenarioCode": "MT01",
  "control": {"previewPlan": false, "allowPartial": true},
  "timeoutMs": 300000
}
```

## 4. 计划契约

`TaskPlan`必须包含`planId/requestId/planVersion/status/nodes/edges/completenessPolicy/permissionSnapshotId/configVersion/createdBy/confirmedBy`。节点包含`taskId/code/type/critical/status/dependsOn/input/outputSchema/timeoutMs/maxAttempts/capabilityVersion`。

计划更新必须携带当前版本；版本不一致返回`409 PLAN_VERSION_CONFLICT`。已确认计划不得原地修改。

## 5. SSE事件

统一事件：`request.received`、`plan.created`、`plan.waiting_confirmation`、`plan.confirmed`、`task.queued`、`task.started`、`task.heartbeat`、`task.succeeded`、`task.failed`、`task.retrying`、`task.cancelled`、`request.partial_success`、`request.failed`、`request.succeeded`。

每个事件包含`eventId,traceId,requestId,planId,taskId,attemptId,eventType,status,occurredAt,payload`。`eventId`在request内单调递增，支持断线续传和去重。

## 6. Java→Python执行命令

```json
{
  "schemaVersion":"2.1",
  "commandId":"uuid",
  "requestId":"uuid",
  "traceId":"trace",
  "plan":{"planId":"uuid","planVersion":1,"nodes":[],"edges":[]},
  "actor":{"subjectId":"uuid","roles":["ROLE_ALL"]},
  "permissionSnapshot":{},
  "configSnapshot":{},
  "deadline":"2026-08-14T12:00:00Z"
}
```

Python只接受Java已签发且匹配request/plan/权限/配置的命令；不得自行扩大计划。Python事件回调必须包含命令ID、任务ID、attempt、状态和事实摘要。

## 7. 错误码

| HTTP | 错误码 | 含义 |
|---:|---|---|
| 400 | DAG_INVALID | 循环依赖、类型或引用非法 |
| 403 | PERMISSION_DENIED | 机构、指标或资产无权 |
| 409 | PLAN_VERSION_CONFLICT | 计划并发修改 |
| 409 | PLAN_CONFIRMATION_REQUIRED | 未确认不能执行 |
| 409 | TASK_NOT_RETRYABLE | 节点状态或错误不可重试 |
| 429 | EXECUTION_QUEUE_FULL | 执行队列已满 |
| 503 | TASK_DEPENDENCY_FAILED | 关键前置失败 |
| 504 | TASK_TIMEOUT | 节点超时 |
| 422 | EVIDENCE_INCOMPLETE | 回答证据不满足完整性 |

## 8. 兼容和安全

- V2.0客户端继续使用原接口；V2.1客户端不得假设旧服务支持计划API。
- 内部调用使用短期服务凭据、TLS和请求签名/受控网络。
- 日志中的SQL、参数、事实和错误按分类脱敏。
- OpenAPI实现文件在M1生成并由契约兼容测试冻结。
