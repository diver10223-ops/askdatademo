# V2.1 用户端与管理端交互规格

## 1. 设计原则

- 沿用参考页面的纵向任务卡，不以复杂DAG画布作为默认交互。
- 业务结果优先，技术参数和SQL摘要默认折叠。
- 等待执行槽、等待依赖、等待确认必须使用不同状态文案。
- 部分成功和未核实项必须在主结果区显示。

## 2. 用户端对话结构

```text
用户问题
系统处理说明/总耗时
计划卡（需要确认时）
任务列表（名称、状态、依赖、耗时）
七层/技术详情（折叠）
综合结果（表格、图表、结论）
完成度、未核实项和证据
推荐追问
```

### 2.1 计划卡

显示计划版本、任务数、预计耗时、关键/非关键、权限范围和确认原因。允许删除非关键节点、增加已注册节点、修改机构/时间/指标筛选、恢复默认；权限/安全/核心事实节点不可删除。

### 2.2 任务卡

| 状态 | 文案 | 操作 |
|---|---|---|
| WAITING | 等待前置任务 | 查看依赖 |
| QUEUED | 等待执行槽 | 取消请求 |
| RUNNING | 执行中 | 展开进度、取消 |
| SUCCEEDED | 已完成 | 查看结果和证据 |
| FAILED | 执行失败 | 查看错误；合法时重试 |
| RETRY_WAIT | 等待重试 | 查看attempt |
| SKIPPED | 前置失败，未执行 | 查看原因 |
| CANCELLED | 已取消 | 无 |

### 2.3 结果区

- SUCCEEDED：完整结果、完成度100%、证据。
- PARTIAL_SUCCESS：黄色状态条、成功/总数、未核实项；禁止完整结论。
- FAILED：展示已验证事实和失败原因，不展示整体判断。
- CANCELLED：展示取消时间、已完成任务，不生成完整结论。

## 3. 任务中心

- 列表字段：问题摘要、场景、状态、完成度、创建时间、耗时、计划版本。
- 筛选：运行中、成功、部分成功、失败、取消、时间和场景。
- 权限：普通用户只看本人；管理员按管理权限查看且数据脱敏。
- 详情：request→plan→task→attempt→fact→answer。

## 4. 管理端

- 场景配置：MT01—MT08、标准问句、角色可见、确认规则和Fixture。
- 任务能力：SQL/计算/汇总Schema、版本、权限、超时和状态。
- DAG模板：节点、依赖、关键性、完整性和版本发布。
- 运行监控：队列、并发、关键路径、重试、取消和部分成功。
- 日志详情：计划diff、权限快照、SQL摘要、attempt、事实和证据。

## 5. 权限和安全交互

- 混合权限默认停止；只显示“无权目标”业务名称，不泄露物理表字段。
- 用户确认仅执行授权部分后显示计划v1→v2差异。
- 角色切换清空当前会话并提示重新提问。
- SQL全文仅对授权管理员展示；普通用户只看到查询能力和口径。

## 6. 原型待产物

开发前需要制作至少：对话自动执行、计划确认、范围收缩、执行中、部分成功、失败重试、取消、任务中心列表和详情九张高保真页面。交互应参照`docs/reference-screenshots/`中任务卡、折叠参数、结构化结果和确认入口。
