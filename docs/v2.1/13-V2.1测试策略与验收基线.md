# V2.1 测试策略与验收基线

## 1. 测试范围

- 七层契约、计划、DAG、权限、SQL安全、调度、重试、取消、恢复、事实、证据和前端交互。
- MT01—MT08×张总/李总/王总×正常/部分成功/失败/取消/重试。
- V2.0 S01—S08完整回归和稳定Demo/POC恢复。

## 2. 测试层级

| 层级 | 内容 | 门禁 |
|---|---|---|
| 单元 | 无环、拓扑、关键性、状态机、公式、重试、取消 | 确定性分支全覆盖 |
| 契约 | 外部API、Java/Python、SSE、Schema | 兼容检查通过 |
| 数据库 | 空库、升级、约束、索引、恢复 | H2/PostgreSQL通过 |
| 集成 | 八场景和三角色 | 状态、事实、答案一致 |
| 安全 | 越权、SQL、提示注入、重试绕权、范围收缩 | 无越权执行/泄露 |
| 性能 | 最大10节点、宽/深DAG、并发、公平性、SSE | 阈值压测后冻结 |
| 恢复 | Java/Python/数据库故障、断线和备份恢复 | 不重复成功节点 |
| 体验 | 计划卡、任务卡、部分成功、任务中心 | 原型验收通过 |

## 3. 标准场景断言

- MT01：同时RUNNING≤3，槽释放即补位，汇总等待关键节点。
- MT02：当期/同期失败时下钻和归因不执行。
- MT03：未确认不查库，计划修改生成新版本。
- MT04：取消幂等，排队/依赖节点终止，完成事实保留。
- MT05：成功节点不重跑，失败节点attempt递增。
- MT06：渠道失败返回PARTIAL_SUCCESS和3/4完成度。
- MT07：关键事实失败返回FAILED，不输出总体判断。
- MT08：权限/配置/时效一致才复用事实。

## 4. 黄金数据

Demo黄金数据使用`fixtures/demo/v2.1/baseline.json`，所有百分比、贡献度和回答证据必须与`08-V2.1八场景标准脱敏演示数据基线.md`一致。POC建立独立批准数据和标准SQL，不以Demo数值冒充真实对账。

## 5. 发布阻断

- P0/P1缺陷未关闭。
- 关键失败仍生成完整结论。
- 并行、重试或上下文可绕过权限/SQL门禁。
- 取消无法传播或服务重启重复执行成功节点。
- Demo、POC、Product任一状态缺少对应制品和证据。
- V2.0回归失败或稳定制品无法恢复。

## 6. 验收证据

每次候选发布保存测试命令、环境版本、提交、迁移版本、场景矩阵、性能报告、安全报告、恢复报告、截图/录屏、Manifest和SHA256。RC通过后原样晋升正式制品。
