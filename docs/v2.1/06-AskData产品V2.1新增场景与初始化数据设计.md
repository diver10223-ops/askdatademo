# AskData 产品 V2.1 新增场景与初始化数据设计

> 状态：数据基线；方案A标准脱敏演示数据已于2026-08-14确认

## 1. 目标

为MT01—MT08提供Demo、POC、Product三种状态所需的场景定义、任务模板、指标资产、权限映射、Fixture、失败注入和验收期望。V2.0 S01—S08及三角色权限保持不变。

## 2. 初始化数据分类

| 数据类别 | Demo | POC | Product |
|---|---|---|---|
| 场景/问句 | 固定MT01—MT08 | 同编号和问题模板 | 同编号正式配置 |
| 机构/角色 | V2.0三角色和脱敏机构 | 批准测试机构 | 正式IAM和机构主数据 |
| 指标 | 脱敏标准指标 | 批准指标和样例结果 | 已发布指标资产 |
| 任务计划 | 确定性DAG模板 | 可由L3生成并与期望比较 | 版本化已发布能力约束 |
| 执行结果 | 固定Fixture | 测试库/真实Provider | 正式数据源，禁止Fixture |
| 失败/取消 | 确定性注入 | 测试故障注入 | 受控演练，不污染生产数据 |

## 3. 必备初始化实体

### 3.1 场景目录

为`flow_scenario`新增MT01—MT08，不修改S01—S08。每个场景至少包括：

- `scenario_code`、名称、版本、启用状态。
- 标准问句、近义问句和多轮追问。
- 允许角色和预期权限行为。
- 计划是否预览、是否强制确认。
- 期望任务节点、依赖、关键性、超时和重试策略。
- 期望整体状态、事实、未核实项和回答结构。

### 3.2 任务能力目录

V2.1首版初始化三类任务能力：

| 能力类型 | 示例 | 边界 |
|---|---|---|
| SQL_QUERY | 单指标、同期、机构/客户类型拆解 | 必须绑定已发布SQL模板和资产权限 |
| CONTROLLED_COMPUTE | 同比、环比、差值、占比、贡献度、排序 | 只允许注册函数和固定输入输出Schema |
| AGGREGATE | 多节点结果汇总、完成度和证据集合 | 不查库、不新增事实 |

### 3.3 任务模板

每个场景初始化`plan_template_version`、节点模板和依赖边。模板用于Demo确定性执行、POC期望对比和Product计划约束，不要求L3每次生成完全相同的节点ID，但业务目标和依赖语义必须一致。

### 3.4 指标和维度

建议首批复用V2.0已发布资产，不新增权限模型：

- 指标候选：贷款投放、存款余额、不良率、中间业务收入、客户数、零售信贷投放。
- 维度候选：机构、客户类型、产品、渠道、月份/季度。
- 受控计算：同比、环比、差值、占比、贡献度和排名。

Demo使用的指标ID、单位、时间粒度和标准值已冻结在`08-V2.1八场景标准脱敏演示数据基线.md`和`fixtures/demo/v2.1/baseline.json`。POC/Product物理字段仍须在目标数据源接入时映射和审批。

## 4. MT01—MT08数据需求

| 场景 | 最少任务数据 | 关键/非关键 | 故障或控制数据 |
|---|---|---|---|
| MT01 | 三机构×三指标或授权范围内等价数据 | 核心对比指标关键 | 一个非关键指标失败样例 |
| MT02 | 当期/同期、客户类型和机构拆解、贡献度 | 当期/同期关键 | 一个下钻维度失败样例 |
| MT03 | 计划v1、用户调整、计划v2和差异 | 权限/核心事实节点不可删除 | 非法节点、越权节点和未确认样例 |
| MT04 | 12个月趋势和机构排名数据 | 趋势主查询关键 | 运行中取消时间线和取消传播结果 |
| MT05 | 三指标结果、一个临时失败及重试成功 | 业务决定 | attempt1失败、attempt2成功和结果复用 |
| MT06 | 投放、余额、不良率、渠道结构 | 前三项关键，渠道建议非关键 | 渠道失败形成PARTIAL_SUCCESS |
| MT07 | 核心指标、基准规则和异常判断 | 核心指标/基准关键 | 关键节点失败，汇总SKIPPED |
| MT08 | 近三个月、同期和极值数据，两轮上下文 | 首轮事实关键 | plan v1/v2、事实复用和权限变化失效样例 |

## 5. 三角色初始化原则

- 张总、李总、王总的角色、机构和指标权限直接复用V2.0初始化数据。
- 新场景只建立角色—场景可见关系和期望回归，不增加权限范围。
- 混合权限问题默认停止；用户确认范围收缩后生成新计划版本。
- 每个Fixture必须带`permissionSnapshotId`和期望权限决定。

## 6. Demo Fixture格式

每个场景建议独立目录：

```text
fixtures/demo/v2.1/MT01/
├── scenario.json
├── plan-v1.json
├── task-results.json
├── event-timeline.json
├── expected-answer.json
└── role-expectations.json
```

`event-timeline.json`必须包含排队、开始、心跳、成功/失败、重试、取消和整体终态的确定性相对时间，不使用真实系统当前时间作为断言。

## 7. POC测试数据

- 使用批准测试Schema和脱敏数据，不使用客户生产数据作为仓库Fixture。
- 提供黄金问题、标准SQL/查询能力、期望行集和业务对账结果。
- 支持临时超时、连接失败和取消等故障注入，禁止用修改真实数据模拟。
- POC缺少真实Provider时明确失败或显式Mock，不静默使用Demo结果。

## 8. Product初始化数据

- 只初始化元数据、配置模板、场景定义和任务能力，不初始化伪造经营结果。
- Product Fixture类型节点默认禁止启用。
- 正式指标、资产、Provider和权限通过审批发布和环境配置导入。
- 初始化脚本必须幂等、版本化、可审计并支持空库和V2.0升级。

- [ ] MT01—MT08均有场景、问句、计划、节点、依赖和期望状态。
- [ ] 三角色期望完全符合V2.0权限矩阵。

- [ ] 初始化和恢复演练通过。
