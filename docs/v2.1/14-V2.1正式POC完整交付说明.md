# V2.1 正式 POC 完整交付说明

## 1. 交付结论

V2.1 正式 POC 已完成代码、配置契约、八场景状态机、用户端呈现和自动化功能验收。正式 POC 运行时必须创建 `PHASE2_POC` Session 并绑定已启用的 Phase 2 Provider Profile；不允许使用 SQLite、Demo Fixture 或确定性回答替代真实模型与真实数据源。

本结论是“可配置、可运行的完整 POC 交付”，不等同于客户环境联通验收或生产交付。

## 2. 真实运行边界

- L2：通过 Profile 配置的 OpenAI-compatible 模型完成结构化任务理解；模型输出只作为候选，指标、机构和日期必须经过发布配置及权限白名单校验。
- L4/L5：任务计划仅引用已发布资产、字段映射和 SQL 模板。
- L6：每个正常查询节点通过 Profile 的 ClickHouse/MySQL Provider 执行安全改写后的参数化 SQL，审计来源为 `REAL_DATASOURCE`，`fallback=0`。
- L7：成功或部分成功场景调用真实模型，输入仅包含已验证事实；关键失败或取消场景跳过模型，由安全策略输出终止结论。
- 任一必需 Provider、凭据、运行配置、模型输出或数据源执行失败时，请求明确失败，不回退到演示结果。

## 3. MT01—MT08

| 场景 | 正式 POC 行为 |
|---|---|
| MT01 | 最大并发 3 的多指标查询，依赖节点等待前置事实，统一汇总成功事实 |
| MT02 | 先核实前置指标，再串行执行关联指标；仅声明发布资产能够支持的分析边界 |
| MT03 | 生成计划 v1 并等待人工确认；确认后生成 v2，未确认不访问数据源 |
| MT04 | 长任务持续检查取消信号；取消传播至任务和数据源，不生成正常完成结论 |
| MT05 | 受控注入首个 attempt 超时，仅重试失败节点；第二个 attempt 使用真实数据源 |
| MT06 | 受控注入非关键节点失败，返回部分成功；模型只能解释成功事实并强制披露未核实项 |
| MT07 | 受控注入关键节点失败，跳过汇总和 L7 模型，由安全策略禁止不完整总体判断 |
| MT08 | 按同会话、同配置、同权限快照、同机构、同指标和同数据时点匹配可复用事实；其余节点重新查询 |

MT05—MT07 的故障由 POC 场景策略控制，不依赖用户在问题中输入“失败测试”“部分成功”等测试字样。

## 4. 用户端

- `/v2.1` 提供 Demo/正式 POC 切换、可用 Profile 选择和八场景快捷入口。
- Demo 与正式 POC 使用不同的标准问题：正式 POC 仅展示当前发布资产支持的指标。
- 任务创建、并发执行、依赖等待、确认、取消、重试、部分成功、安全终止及事实复用均按事件和后端状态逐步展示。
- 过程区与最终 AI 对话区保持视觉区分；最终回答逐字输出并自动跟随滚动。
- Provider 失败时显示失败层、错误类型和安全摘要，并说明没有使用演示数据或降级结果。

## 5. 自动化证据

- Python 后端全量：65 项通过。
- 正式 POC 八场景协议级功能验收：覆盖真实 Provider 调用边界、`REAL_DATASOURCE`、无 fallback、确认、取消、重试、部分成功、安全终止和事实复用。
- 前端：TypeScript 类型检查、在线构建、离线构建通过。

按项目统一测试边界，所有版本均不执行冒烟测试和长时间稳定性测试；上述验收使用协议测试替身，不主动访问真实模型或真实数据源。因此，具体客户 Profile 的额度、网络、模型名、Schema 和业务数据正确性需在客户明确要求的功能验收中单独确认。

## 6. 已知限制

- 当前发布资产仅包含贷款投放、零售贷款和对公贷款及其同期字段；未发布的存款、不良率、中收、客户类型和机构贡献度不会在正式 POC 中伪造。
- MT02 的客户类型/机构贡献度下钻只有在相应明细资产、字段映射和 SQL 模板发布后才能形成真实归因。
- MT05—MT07 是 POC 的受控故障策略，不是生产故障编排平台。
- 本交付不包含容量结论、长稳结论、生产 SLA 和客户环境联通结论。
