# 修改分析归档规范

本目录用于归档用户确认后的功能修改分析与实施记录，不存放产品源代码或运行数据。

## 文件分类

每个修改范围按日生成以下五类文件：

1. `需求分析.md`：原始需求、范围、验收标准、非目标和风险。
2. `修改流程分析.md`：页面交互、前后端链路、状态变化和实际修改记录。
3. `接口库表修改.md`：接口入参出参、兼容性、数据库表及迁移影响；无修改时也要明确记录“无”。
4. `架构修改.md`：组件职责、配置结构、详细设计、兼容策略和安全边界。
5. `执行规划.md`：实施步骤、检查点、测试项、结果和遗留事项。

## 强制内容

每次修改分析必须可以从需求追踪到代码和数据，不允许只记录结论。对应文件至少包含：

- 需求影响的用户端/管理端功能和功能点。
- 涉及的数据库、表、字段、主外键或JSON字段；无库表修改时也必须写明读取了哪些表以及为什么无需修改。
- 直接关联表和上下游数据关系。
- 新增、修改、删除或仅验证的接口，以及请求/响应字段。
- 涉及的源码、配置、测试和文档文件，标明其中的类、函数或组件。
- 修改前链路、修改后链路及兼容/迁移链路。
- Mermaid流程图或链路图，逐节点标注页面、接口、服务和库表。
- 文件—功能—接口—库表四维核对表，确保没有遗漏。

推荐直接复制 [修改分析模板.md](./修改分析模板.md) 后按日期和功能重命名。

## 命名规则

- 用户端：`用户端YYYYMMDD{文件分类}.md`
- 管理端：`管理端YYYYMMDD{一级菜单名称}{文件分类}.md`
- 日期统一使用8位自然日，例如 `20260807`。
- 管理端跨菜单修改归入“管理首页”；单一功能修改必须归入对应一级菜单。
- 同日同范围继续修改时更新原文件并追加小节，不重复创建同名文件。

## 当前归档范围

- 用户端：对话消息和执行轨迹展示。
- 管理首页：管理端全局导航、字号和公共布局。
- 用户权限：功能权限命名与字段口径。
- 数据字典：指标、维度、数仓、字段映射和推荐演示数据。
- 流程配置：SQL模板展示数据。
- 模型配置：多模型提供商、模型联动选择与独立加密配置。
- 数据源配置：独立数据源连接、启用与诊断。
- 系统运维：模型和数据源的引用式运行组合。
